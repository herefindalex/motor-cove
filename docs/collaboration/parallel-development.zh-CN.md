# 并行开发

[English](parallel-development.md) · [繁體中文](parallel-development.zh-TW.md)

本页解释了哪些工件可以让工作独立进行，哪些门仍然存在硬依赖关系。

前端、API、Indexer、数据库和协议可以根据经过审核的 ABI、Zod/OpenAPI、部署清单、包导出、Drizzle 模式契约和显式测试装置进行开发。应用程序不得通过源导入另一个应用程序来解锁工作。

ABI 夹具可以在部署之前解锁 UI 状态和解码器单元测试。读卡器接口可以在 Indexer 集成之前解锁 API 演示器。这些模拟不能满足实际部署、原子摄取或浏览器 E2E 门。

合约和模式变更伴随着生成的工件、提供者测试、消费者兼容性测试、迁移/重建影响、恢复路径和更新的证据元数据。功能分支使用存储库命名策略，并且不提交本地数据库、清单、备份、跟踪或机密。

仅当 API 和 Indexer 消费者合约测试在同一工作树中通过时，数据库提供程序更改才完成。纯源提供商测试可以并行进行，但它们不能满足消费者的要求。
