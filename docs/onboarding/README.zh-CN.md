# 贡献者入门

[English](README.md) · [繁體中文](README.zh-TW.md)

此页面帮助每个工程角色找到安全的首要任务、可能更改的合约以及最小的有意义的验证。从[贡献](../../CONTRIBUTING.zh-CN.md) 和[项目范围](../project-scope.zh-CN.md) 开始。

## 前端

1. 将市场路由从 `apps/web/src/app/App.tsx` 追踪到特征公共索引。
2. 将隔离的 UI 状态添加到 Storybook 故事中，而无需将 SDK 导入到功能/模型代码中。
3. 运行 Web 类型检查、Storybook 构建、架构检查和相关浏览器场景。

共享合约：API Zod 模式、链 ABI、部署配置、交易日志模式。

## 协议

1. 一起阅读 `IMotorCoveEscrow.sol`、实现、单元测试和不变处理程序。
2. 在更改转换或资产转移之前添加错误路径测试。
3. 重新生成 ABI 工件并列出受影响的前端、解码器、投影器和文档使用者。

共享合约：ABI、事件、自定义错误、清单协议版本。

## API 和后端

1. 通过路由、用例、阅读器端口、演示者和 Zod 模式跟踪 `/v1/sales/{saleId}`。
2. 在更改传输数据结构之前添加响应字段测试。
3. 仅保留 API 读取器，切勿导入投影写入器或维护导出。

共享合约：API 模式/OpenAPI 和数据库读取器 DTO。

## Indexer

1. 跟踪来自 Viem 的一个事件，通过纯投影器解码到 SQLite 适配器中。
2. 添加针对无效排序的纯投影器测试或具有受控边界的摄取测试。
3. 保留顺序、源身份、原子检查点行为以及检测和停止语义。

共享合约：ABI 事件、投影器版本、日志范围、数据库投影 writer。

## 数据库和操作

1. 运行四个临时数据库套件；不要将练习指向现有工作区数据库。
2. 更改 Drizzle 架构并生成一份经过审核的正向迁移加架构合约。
3. 测试全新安装、历史篡改、约束、锁定、标记和恢复边界。

共享合约：SQL 历史记录、模式合约、包导出、环境布局、根命令。

## 质量保证和交付

1. 将场景 ID 映射到其源、测试选择器、环境级别和限制。
2. 添加一个负固定装置来证明新的检查器规则可能会失败。
3. 将本地、真实的 SQLite、真实的 Anvil、浏览器自动化和手动钱包证据分开。
