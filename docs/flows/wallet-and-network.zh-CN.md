# 钱包和网络流量

[English](wallet-and-network.md) · [繁體中文](wallet-and-network.zh-TW.md)

此页面跟踪连接、链验证、拒绝和交易上下文保存。

## 权威来源及连接器方式

在正常操作中，用户控制注入的 EIP-1193 钱包。连接将帐户和链公开给 Web 应用程序；它不是登录、后端身份验证或密钥保管。

本地演示可以明确设置 `VITE_MOTORCOVE_DEMO_WALLET=1`。然后，前端添加两个由解锁的 Anvil 卖家和买家地址支持的 Wagmi 模拟连接器。此模式仅限于 Vite 开发服务器和环回 RPC。它嵌入公共测试地址，而不是私钥。连接器仍然向 Anvil 提交真实的 JSON-RPC 交易。

## 流量

1. `WagmiProvider` 公开注入的连接器，并在显式启用时公开本地演示
   `apps/web/src/app/composition.tsx` 连接器。
2. 当浏览器没有提供程序时，钱包集成会过滤掉注入的连接器。的
   功能呈现可操作的不可用状态，而不是死连接按钮。
3. 用户选择连接器。连接错误在重试控件旁边仍然可见。
4. 该功能派生出断开连接、错误网络和连接状态。
5. 一项功能要求其 EVM 端口模拟针对当前部署的合约调用。
6. 钱包可能会拒绝、切换链或提交。持久意图是在请求之前记录的。
7. 交易观察者遵循一个已知的哈希值，独立于以后的账户或链的变化。

## 失败与恢复

在打开钱包请求之前，网关会保存待处理的意图，并通过公共 RPC 和钱包提供商验证预期的部署。它将公共链 ID、钱包客户端链 ID 和每个提供商的托管 `deploymentId()` 与不可变的意图进行比较。此检查还涵盖代币批准。不匹配或不可用的证明在钱包写入并记录 `FAILED_BEFORE_SUBMIT / OPERATION_ENVIRONMENT_MISMATCH` 之前停止。后来的钱包结果仍然遵循正常的哈希和未知结果恢复规则。

拒绝可以安全地作为新的用户决定重试。未知的提交结果则不然。帐户或链的更改不得删除先前操作存储的不可变帐户、链、合约、操作、随机数或哈希值。重新加载仅恢复具有足够证据以进行查询而无需提交的条目。

自动浏览器覆盖范围有两个不同的范围：本地演示连接器证明正常的环回交易路径，而受控的 EIP-1193 提供商则注入拒绝、传输丢失、帐户更改和网络更改。也没有证据表明 MetaMask 或其他浏览器扩展是手动执行的。

证据：`TX-001`，`TX-002`；源位于 `capabilities/wallet`、`capabilities/transactions` 和 `integrations/evm` 下。下一页：[交易生命周期](../protocol/transaction-lifecycle.zh-CN.md)。

## 证据同一性和持久性失败

如果钱包返回哈希，但日志无法持久保存提交的状态，则 UI 将操作上下文保留在内存中，显示可复制哈希并显示非持久警告，并在当前选项卡中继续只读观察。在此状态下，重新加载恢复受到明确限制。未能坚持初始意图仍会在任何钱包请求之前停止。

反映的投影结果与观察到的交易哈希、块哈希、日志索引、部署和投影构建绑定。在不同的块或日志中重新包含相同的事务会使 API 查找之前的当前反射无效。 API 中断可能会保留相同身份的历史证据，但不能提升先前身份的证据。
