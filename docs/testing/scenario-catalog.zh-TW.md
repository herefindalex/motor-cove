## R7恢復和並發覆蓋率

- **TX-002：** 最終的即時情境檢查發生在等待的持久性之後
  `AWAITING_WALLET` 寫入。每個操作的修訂都會拒絕過時的日誌更新，並且 Chromium 會在不使用掛鐘順序的情況下驗證多選項卡寫入器切換。
- **IDX-003：** 中斷的重新索引即使在頭部之後也會恢復儲存在其標記中的目標
  進步。錨點更改、恢復身份不匹配以及格式錯誤的標記案例無法關閉並釋放其維護鎖定。
- **IDX-004：**任何範圍、解碼器或來源摘要刷新都需要經過驗證的環境備份
  在刪除活動原始事件或標頭之前記錄在標記中。檔案裝置證明移位的來源證據仍可讀。

資料庫接受 ID `DB-01` 到 `DB-75` 維護在 [資料庫接受矩陣](database-acceptance-matrix.zh-TW.md) 中。文檔驗收 ID `DOC-01` 到 `DOC-32` 維護在[文檔驗收矩陣](documentation-acceptance-matrix.zh-TW.md) 中。

## R24部署證明和即時覆蓋

- **TX-001 / REL-001：** 提交前回歸測試將不可變意圖與公眾進行比較
  RPC 和錢包提供者部署身分。任何不匹配或不可用的證明都會在錢包寫入之前停止；匹配的證據允許一次提交。
- **IDX-001：**整合回歸測試將固定目標追趕率保持在低於即時合格水平的水平
  僅在有效收斂後才發布 `CURRENT` 並允許 `CURRENT`。
- **REL-001：** API 測試允許一個配置的前端來源並拒絕不同的本地
  預設 CORS 策略下的主機名稱。

## R25 恢復和引導證據覆蓋

- **IDX-003 / IDX-004：** 持久的 `RECOVERY_REQUIRED` 在正常寫入器啟動、過時/目前狀態下仍然存在
  轉換和普通提交嘗試。規範/來源原因拒絕在標記發布之前重建； reindex透過重播保留原因，只有在目標證明後才釋放。僅投影器重建在本地來源驗證後仍然符合資格。
- **DB-30 / DB-71：** 收據 JSON 必須具有預期的架構和環境/部署標識。
  發布會保留經過驗證的歷史最終收據，拒絕格式錯誤或衝突的最終收據，並且成功後不會留下任何臨時文件。標準備份和後製驗證都可以驗證收據內容。
- **IDX-001：**僅本地日誌重建留下最後成功的 RPC 和工作器心跳時間
  未受影響，因此儘管投影重播成功，觀察新鮮度仍可能保持陳舊。
