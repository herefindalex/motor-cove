## R7恢复和并发覆盖率

- **TX-002：** 最终的实时上下文检查发生在等待的持久性之后
  `AWAITING_WALLET` 写入。每个操作的修订都会拒绝过时的日志更新，并且 Chromium 会在不使用挂钟顺序的情况下验证多选项卡写入器切换。
- **IDX-003：** 中断的重新索引即使在头部之后也会恢复存储在其标记中的目标
  进步。锚点更改、恢复身份不匹配以及格式错误的标记案例无法关闭并释放其维护锁。
- **IDX-004：**任何范围、解码器或源摘要刷新都需要经过验证的环境备份
  在删除活动原始事件或标头之前记录在标记中。档案装置证明移位的源证据仍然可读。

数据库接受 ID `DB-01` 到 `DB-75` 维护在 [数据库接受矩阵](database-acceptance-matrix.zh-CN.md) 中。文档验收 ID `DOC-01` 到 `DOC-32` 维护在[文档验收矩阵](documentation-acceptance-matrix.zh-CN.md) 中。

## R25 恢复和引导证据覆盖

- **IDX-003 / IDX-004：** 持久的 `RECOVERY_REQUIRED` 在正常写入器启动、过时/当前状态下仍然存在
  转换和普通提交尝试。规范/来源原因拒绝在标记发布之前重建； reindex通过重播保留原因，只有在目标证明后才释放。仅投影器重建在本地源验证后仍然符合资格。
- **DB-30 / DB-71：** 收据 JSON 必须具有预期的架构和环境/部署标识。
  发布会保留经过验证的历史最终收据，拒绝格式错误或冲突的最终收据，并且成功后不会留下任何临时文件。标准备份和后期验证都可以验证收据内容。
- **IDX-001：**仅本地日志重建留下最后成功的 RPC 和工作器心跳时间
  未受影响，因此尽管投影重放成功，观察新鲜度仍可能保持陈旧。
