# 项目范围

[English](project-scope.md) · [繁體中文](project-scope.zh-TW.md)

此页面定义了 MotorCove 演示的内容及其声明的停止位置。

## 范围内

MotorCove 为本地测试资产建模了一个狭窄的 ERC-721 市场。产品表面包括注入钱包流程、批准和托管列表、确切价格融资、完成或到期、基于拉取的收益和退款、NFT 回收、事件派生的读取模型、只读查询 API 和本地数据库生命周期工具。

工程范围包括强制模块边界、生成的 ABI 和 HTTP 合约、部署身份、持久事务观察、替换和重组分类、重播/重建/重新索引/对账、迁移历史、维护协调、本地 CI 门和贡献者切换。

## 验证本地恢复边界

- 一次真实的 Anvil 广播后丢失的钱包响应可以通过提供重新加载后恢复
  交易哈希。恢复是只读的，不会再次提交。
- 相同随机数替换分为 `REPRICED`、`CANCELLED` 或 `DIFFERENT_CALL`。
  孤立的收据证据变为 `NONCANONICAL`，并且相同哈希重新包含记录新的规范收据和事件身份。
- 真实的SQLite案例涵盖本机迁移历史和失败回滚，锁所有者`SIGKILL`，
  受控 `SQLITE_BUSY`、有界 `SQLITE_FULL`、重播、重建、规范重新索引、实时头后面的备份恢复以及单快照 API 读取。
- 当其部署标识已被拒绝时，重用确定性合约地址的重置将被拒绝。
  改变了。重置CLI拒绝非环回RPC、错误的链ID和非Anvil客户端。
- 对账使用锚定的 `saleCount` 和 `nextTokenId` 来检测完全缺失的销售并
  每个铸造代币的所有权行。

## 当前的实施或验证差距

- 链广播到哈希日志窗口中的真实进程终止不会被注入。确定性
  日志测试证明了已知哈希恢复和围绕该边界的保守 `UNKNOWN` 行为。
- 第一次架构升级具有保留数据 `0000` 到 `0001` 固定装置。兼容性
  存储库记录的迁移历史之外的架构仍未得到验证和支持。
- 受控 SQLite 页面耗尽证明原子回滚，但不模拟完整主机
  文件系统。 `SIGKILL` 不证明控制器缓存、文件系统刷新或硬件断电耐久性。
- 手动 MetaMask 提示和提供商特定的行为未经验证。浏览器自动化使用
  受控 EIP-1193 适配器。
- GitHub Actions 运行是特定于提交的，并且与本地证据分开记录。分公司
  保护、所需审阅设置和存储库审阅者身份仍然需要所有者配置并且仍未得到验证。

## 非目标

- 实体车辆所有权、交付、融资、税收或法定所有权。
- 主网或公共测试网部署、真实货币或有价值的资产。
- 后端身份验证、SIWE、钱包托管、密钥管理或自动签名。
- 生产数据库服务、跨主机SQLite、在线迁移或零停机恢复。
- 自动修复每个链不匹配、通用公共网络重组策略或恰好一次
  链式交易。
- 外部安全审计、生产负载测试、团队速度或实际团队使用的声明。

## 安全边界

只有环回 Anvil、链 ID `31337`、合成账户、测试 ETH 和测试资产属于演示工作流程。维护命令需要 `.motorcove/environments/<id>` 下的自有环境，并且不得指向任意数据库。仅使用具有一次性环境 ID 的破坏性演示命令。预先存在的 `data/motorcove.sqlite` 文件位于托管路径之外，并且永远不会自动采用或重置。
