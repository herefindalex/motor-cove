# 資料權威來源

[English](data-authority.md) · [简体中文](data-authority.zh-CN.md)

此頁面回答了哪個元件可以提出每個聲明以及哪些記錄可以重建。

| Claim                  | 權威來源                | 當地證據                     | 重建或備份規則                                   |
| ---------------------- | ----------------------- | ---------------------------- | ------------------------------------------------ |
| NFT 所有者和轉讓       | 規範合約歷史            | 傳輸日誌和所有權投影         | 投影可以從經過驗證的完整歷史記錄中重建           |
| Sale 狀態與截止日期    | 託管合約                | 託管事件加上錨定鏈讀取       | 投影可以重建；沒有 SQL 種子可以發明狀態          |
| 付款索賠和提款         | 託管合約                | Claim 事件與合約取得者       | 保持受益人、金額、種類、身分和接受者的明確性     |
| 目錄複製和本地圖像映射 | SQLite 目錄表           | 目錄行和部署範圍的資產綁定   | 權威的鏈下資料必須在投影重建後倖存下來並需要備份 |
| 交易觀察               | 錢包/RPC 觀察記錄的意圖 | 瀏覽器日誌，哈希，收據，替換 | 不寫伺服器投影                                   |
| 投影新鮮度             | Indexer 檢查點與觀察頭  | API 出處與運行時狀態         | 新鮮度和比較與正確性是分開的                     |

SQLite是一個混合權威來源資料庫。稱其為「快取」將使目錄編輯和綁定看起來是一次性的；調用每一行權威將隱藏鏈派生的投影需要重播或重新索引。完整備份會保留這兩個類別。 投影重建僅取代派生表。

請參閱[資料庫架構](database.zh-TW.md)、產生的[資料庫架構參考](../database/schema-reference.generated.zh-TW.md) 以及整理的[權威來源和生命週期矩陣](../database/authority-and-lifecycle.zh-TW.md)。
