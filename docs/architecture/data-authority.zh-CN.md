# 数据权威来源

[English](data-authority.md) · [繁體中文](data-authority.zh-TW.md)

此页面回答了哪个组件可以提出每个声明以及哪些记录可以重建。

| Claim                  | 权威来源                | 当地证据                     | 重建或备份规则                                   |
| ---------------------- | ----------------------- | ---------------------------- | ------------------------------------------------ |
| NFT 所有者和转让       | 规范合约历史            | 传输日志和所有权投影         | 投影可以从经过验证的完整历史记录中重建           |
| Sale 状态和截止日期    | 托管合约                | 托管事件加上锚定链读取       | 投影可以重建；没有 SQL 种子可以发明状态          |
| 付款索赔和取款         | 托管合约                | Claim 事件和合约获取者       | 保持受益人、金额、种类、身份和接受者的明确性     |
| 目录复制和本地图像映射 | SQLite 目录表           | 目录行和部署范围的资产绑定   | 权威的链下数据必须在投影重建后幸存下来并需要备份 |
| 交易观察               | 钱包/RPC 观察记录的意图 | 浏览器日志，哈希，收据，替换 | 不写服务器投影                                   |
| 投影新鲜度             | Indexer 检查点和观察头  | API 出处和运行时状态         | 新鲜度和比较与正确性是分开的                     |

SQLite是一个混合权威来源数据库。称其为“缓存”将使目录编辑和绑定看起来是一次性的；调用每一行权威将隐藏链派生的投影需要重播或重新索引。完整备份会保留这两个类。 投影重建仅替换派生表。

请参阅[数据库架构](database.zh-CN.md)、生成的[数据库架构参考](../database/schema-reference.generated.zh-CN.md) 以及整理的[权威来源和生命周期矩阵](../database/authority-and-lifecycle.zh-CN.md)。
