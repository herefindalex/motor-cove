# 如何選擇重建或重新索引

[English](projection-rebuild-and-reindex.md) · [简体中文](projection-rebuild-and-reindex.zh-CN.md)

停止 API 和 Indexer 並確定正常追趕無法繼續的原因後，請使用此 Runbook。

## 選擇來源

- **重建** 僅當本地標頭/原始日誌完整、內容經過驗證、範圍正確且
  錨定。在一個維護版本中刪除/重新建立衍生的投影行，同時保留目錄。
- 當歷史記錄、規範分支、解碼器範圍或日誌完整性受到懷疑時，**重新索引**。獲取
  來自已驗證部署的 RPC 的標頭和原始日誌，然後重建。
- **新部署** 當部署 getter、程式碼雜湊或清單標識發生變更時。不治療它
  作為普通的重組。

## 命令

```bash
MOTORCOVE_ENV=<id> pnpm ops:rebuild
MOTORCOVE_ENV=<id> pnpm ops:reindex -- --yes
```

重建將經過驗證的本地來源證據重播到新的投影版本中。重新索引驗證環回部署身份，從請求的區塊倒回，保留移位的來源證據，重新取得規範標頭和日誌，並捕獲捕獲的目標。

## 成功條件

成功需要一個新的 `projectionBuildId`、保留的目錄/綁定、按規範順序重播所有適用的來源事件、到達經過驗證的檢查點以及同一塊/哈希上的對帳。故障不得暴露半成品投影。

請參閱[索引流程](../flows/indexing-and-recovery.zh-TW.md) 和 [對帳](reconciliation.zh-TW.md)。

## 恢復中斷的操作

使用 `pnpm ops:recover --env <id>` 檢查標記。對於`REBUILD_PROJECTION`和`REINDEX_PROJECTION`，`--complete`有意返回`ACTION_REQUIRED`；它不會清除標記。停止運行時並重新執行相同的重建命令，或使用原始 `--from` 值重新執行相同的重新索引命令。復原需要匹配操作類型、部署、回滾點、捕獲的目標區塊和目標雜湊。恢復的命令驗證並重複使用標記的原始目標；當活頭前進時，它不會移動目標。遺失或變更的目標錨點在再次倒回之前仍處於鎖定狀態。

## 源預檢和維護相容性

在重建更改投影行之前，它會驗證從部署掃描開始到檢查點的連續規格和掃描完成標頭。每個區塊的觀察計數和摘要必須與儲存的事件行匹配，並且每個事件必須保留其原始信封、解碼事件和解碼器版本綁定。 `REBUILD_SOURCE_INCOMPLETE` 保留現有的投影；使用重新索引重新取得來源而不是編輯日誌行。

具有該確切錯誤的失敗重建可能會在同一獨佔維護門下轉換為完整重新索引。重新索引必須從部署掃描開始區塊開始，擷取並驗證目標區塊/哈希，並匹配標記的環境、資料庫、部署和架構契約。新標記接收新的操作 ID 並將失敗的重建操作 ID、類型和錯誤記錄為沿襲。其他失敗的重建原因、部分重新索引範圍和隱式標記變更仍然被阻止。

Reindex 捕獲 `head - indexingDepth` 及其雜湊值作為完成目標。非零深度不會等待不合格的活頭，閒置鏈不需要額外的交易來完成。如果目標雜湊在捕獲時發生更改，則重新索引會在維護倒回之前停止。

如果操作員在資料庫已經投影更新的區塊後增加索引深度，則正常攝取會停止並顯示 `CHECKPOINT_EXCEEDS_ELIGIBLE_TARGET`。從部署掃描開始執行重新索引，以便其固定的合格目標和重建的投影強制執行新的保留。請勿清除恢復原因或手動降低檢查點。減少深度不需要重建並且可以正常地向前趕上。

運行時啟動拒絕投影器或日誌範圍不符。維護僅接受明確支援的先前投影器版本。僅當重新索引在部署掃描開始區塊開始時才允許範圍變更。

## 來源刷新歸檔邊界

當受支援的範圍、解碼器或來源-摘要轉換需要取代儲存的標頭和事件時，重新索引會在現有的獨佔維護閘下建立並驗證環境備份。在刪除活動來源行之前，它會將經過驗證的備份 ID 寫入重新索引標記。中斷的復原會再次驗證記錄的備份。如果備份建立、校驗和驗證或標記持久性失敗，活動來源日誌保持不變。

备份保留先前的 SQLite 源行，包括移位的或孤立的证据。重新索引仍然僅重新取得活動建置所需的規範範圍；備份是診斷和復原證據，而不是 RPC 可以重現歷史孤立日誌的承諾。

在重新索引準備之前立即評估來源刷新分類。當非空事件行的原始信封、解碼的有效負載、解碼器版本、來源記錄摘要或已完成區塊的相同計數摘要不一致時，需要重新整理。重新索引必須從部署掃描開始區塊開始，記錄並驗證備份，然後重新取得規範來源。純粹的缺失事件行遵循普通的倒帶和重新插入，而不是被錯誤地標記為矛盾的內容。 `EVENT_IDENTITY_CONTENT_MISMATCH` 在正常攝取期間仍然是硬故障。

## 驗證來源快照身份

正常的追趕和重新索引在日誌之前取得標頭，然後使用精確觀察到的區塊雜湊值請求日誌。合規的鏈提供者必須支援 EIP-234 區塊哈希日誌過濾器。 MotorCove 不会将数字范围内的日志与该请求后观察到的标头结合起来。

當診斷顯示標頭/日誌身分錯誤時：

1. 保留目前檢查點和維護標記。
2. 确认配置的 RPC 可以通过块哈希为部署范围提供日志。
3. 傳輸運行狀況恢復後，重新運行相同的重新索引操作。
4. 不要編輯掃描完成的元資料或來源行來強制進度。

為本地 Indexer 傳輸啟用了 JSON-RPC 批次處理，因此每個標頭身分檢查不會將較大的追趕範圍轉換為序列化的 HTTP 往返。

## 恢復長時間重建索引

重新索引可能需要超過 1,000 個成功批次。該命令將運行直到達到其固定的合格目標，前提是每次成功的迭代都會推進持久檢查點。

標記的`projectionPhase`決定安全恢復：

- `PREPARING`：此操作仍可執行其擁有的來源倒帶和投影準備。
- `CATCHING_UP`：使用相同的 `--from` 值重新執行相同的命令。它重建派生的投影
  從保留的來源證據中陳述並從檢查點繼續，而不會再次倒回。

`REINDEX_CATCHUP_NO_PROGRESS` 表示適配器成功返回，但沒有推進持久狀態。保留標記，檢查檢查點和提供者回應，然後僅在糾正原因後恢復。不要清除標記或啟動新目標來繞過此錯誤。

## 持續恢復原因

不要使用重建來清除規格或來源完整性原因，例如檢查點雜湊變更、父級不連續性、日誌區塊雜湊不符或高於合格索引目標的檢查點。維護命令在更改其標記之前拒絕該操作。使用明確重新索引路徑。 投影器-only完整性可以在本地原始來源通過驗證後使用重建。失敗的重建索引保留其標記和復原要求；恢復匹配操作而不是啟動運行時編寫器。已完成的固定重新索引目標進入 `SYNCING`，直到即時合格的頭部觀察支援 `CURRENT`。
