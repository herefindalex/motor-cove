# 資料庫備份、還原與復原操作

[English](backup-restore-and-recovery.md) · [简体中文](backup-restore-and-recovery.zh-CN.md)

僅將這些指令用於已停止 API 和 Indexer 的自有 `.motorcove` 環境。

## 建立快照

標準備份在維護服務/寫入器鎖定之前取得共用引導程式所有權。因此，活動引導或恢復在快照工作之前返回 `RESOURCE_BUSY`。僅包含 `seed-journal.json` 和 `bootstrap-receipt.json` 之一的部署快照是不完整的，並且不是可還原的標準備份。

```bash
pnpm db:backup --env docs-smoke
```

此指令使用 SQLite 備份 API，驗證完整性、外鍵、模式契約和本機歷史記錄，然後發布包含校驗和、來源準備情況、復原策略和投影證據的格式 3 捆綁包。標準備份要求不存在維護標記。它不會複製 Anvil 狀態、金鑰或錢包日誌。

遷移安全性和來源刷新存檔呼叫在現有維護所有者內部運作。他們必須綁定當前操作ID和目的。它們的捆綁包是 `EVIDENCE_ONLY`：它們保留來源檢查點、建置、範圍、狀態、復原原因以及用於復原或診斷的標記標識，但正常的復原命令不會安裝它們。

## 顯式恢復

恢復在維護鎖定之前取得獨佔引導程式所有權。在隔離之前，它需要活動的 `deployment.json`、`seed-journal.json` 和 `bootstrap-receipt.json` 存在以及位元組以匹配已驗證的備份。僅資料庫復原會拒絕 sidecar 不匹配，而不是組合兩個引導生成。

```bash
pnpm db:restore --env docs-smoke --backup <verified-backup-id> --yes
```

還原驗證來源包，將其資料庫複製到操作擁有的暫存，並在移動活動檔案之前對暫存位元組重複清單 SHA-256 檢查。然後，它隔離目前的主 DB 和 WAL/SHM sidecar，安裝獨立快照，使用 WAL 策略開啟它，並再次驗證。跨驗證/複製邊界的來源變更在隔離之前失敗。 `--yes` 確認破壞性選擇；它不會繞過所有權或校驗和防護。資料庫復原永遠不會回滾鏈。復原僅接受記錄來源條件為 `READY` 的 `STANDARD` 快照。

## 恢復中斷的操作

```bash
pnpm ops:recover --env docs-smoke
pnpm ops:recover --env docs-smoke --complete
```

第一個命令報告標記。只有當活動、暫存或隔離的候選者成為經過驗證的資料庫後，`--complete` 才會重新取得鎖定並清除標記。切勿將刪除 `maintenance.json` 作為正常恢復方法。

標記發佈為每次更新使用新的專有臨時檔案名，然後透過 `maintenance.json` 自動重新命名並同步目錄。發布的標記具有權威性。如果進程在重命名之前終止，則匹配的復原會忽略該未發布的文件，並在下次成功發布後刪除孤立的臨時文件。操作員不得手動升級或刪除標記臨時檔案。

報告命令可以讀取沒有所有權的標記，因為它只是預覽。 `--complete`路徑先取得環境維護鎖，然後再次讀取標記；所有恢復選擇和突變都使用該鎖擁有的快照。在鎖定獲取之前觀察到的標記永遠不會用於清除或完成操作，因為在命令等待時另一個所有者可能已替換它。

SQLite main、WAL、SHM 檔案為一代。如果僅移動活動主檔案後恢復停止，則復原會先將剩餘的活動 sidecar 移至同一隔離區，然後再安裝暫存的獨立快照。如果它從隔離區回滾，它會重新組合該隔離區的主車和邊車。活動位置和隔離位置的重複 sidecar 不明確；恢復會停止並保留標記，而不是選擇一個。

## 停止條件

出現校驗和/身分不匹配、候選缺失、模式漂移、歷史分歧或鏈部署不匹配時停止。保留標記、隔離和報告以供診斷。

臨時測試涵蓋 WAL 快照、損壞的備份拒絕、驗證復原以及進程終止的熱 WAL 檔案切換崩潰視窗。硬體斷電、恢復後的鏈前追趕以及所有檔案系統故障模式均未驗證。

## 源模式備份證據

備份驗證完整性、外鍵、作為儲存庫遷移包的已知前綴的本機歷史記錄，以及針對資料庫自己的 `db_contract` 行的即時模式指紋。清單記錄了快照的實際遷移計數、前綴摘要、架構指紋和來源合約版本。它沒有將快照描述為已經處於未來的目標模式。

對於遷移前快照，成功發布是一個持久的遷移階段。遷移標記儲存已發布的備份ID，且每個符合的還原在應用SQL之前再次呼叫普通備份驗證器。它還將經過驗證的快照證據與即時來源資料庫和部署身分進行比較。失敗的備份不會留下任何證據，因此下一次匹配運行必須重試備份建立。記錄證明後的失敗將重複使用相同的經過驗證的快照。

還原目前僅安裝與執行程式碼的目標架構相符的快照。在行動活動資料庫之前，有效的舊快照會失敗並顯示 `BACKUP_REQUIRES_MIGRATION`；透過遷移工作流程升級它，而不是繞過防護。中断的投影重建或重新索引将保持 `ACTION_REQUIRED`，直到匹配的投影命令完成。

RESET有自己的竣工合約。 `PREPARED`表示鏈上結果未經證明，返回`ACTION_REQUIRED / RERUN_MATCHING_RESET`；恢復不會檢查舊資料庫並稱其成功。 `CHAIN_RESET` 或 `LOCAL_STATE_CLEARED` 允許恢復在獨佔引導和維護所有權下完成產生狀態刪除。備份、受管節點綁定、所有權和穩定鎖定檔案保留在刪除集之外。

## 部署和 sidecar 身份

備份格式 3 記錄明確部署狀態。 `DEPLOYED` 快照绑定数据库部署 ID 并记录部署、引导接收和种子日誌 sidecar 的存在和 SHA-256 证据。 `PREDEPLOYMENT` 快照僅在資料庫部署行數為零且所有三個 sidecar 均不存在時才有效。這使得遷移可以保護初始化的預先部署資料庫，而無需發明鏈身分。預先部署快照中的 sidecar，或已部署快照中遺失或變更的 sidecar，驗證失敗。

在建立隔離目錄之前，還原會將已部署的備份與活動資料庫和活動部署清單進行比較。相同環境名稱的早期部署的備份將被拒絕。部署前備份是遷移證據，目前從復原命令返回 `BACKUP_PREDEPLOYMENT_RESTORE_UNSUPPORTED`；它們不是作為部署環境安裝的。

恢復不會安裝 sidecar、重置 Anvil、部署合約或重播種子交易。移動整個環境需要一個單獨的、明確的工作流程；資料庫恢復適用於相同的部署身份，並且可能隨後是正常的 Indexer 追趕。

## Bootstrap 收據證據

已部署環境的標準快照需要配對種子日誌和可解析的、身份綁定的引導收據。備份會在發布之前驗證複製的收據，即使記錄的校驗和匹配，備份驗證也會再次檢查其架構和身分。無法透過編輯備份或從其他部署複製收據來修復遺失或格式錯誤的收據。在進行標準備份之前，透過其擁有的工作流程解決不完整的引導程序。
