# 数据库备份、还原与恢复操作

[English](backup-restore-and-recovery.md) · [繁體中文](backup-restore-and-recovery.zh-TW.md)

仅将这些命令用于已停止 API 和 Indexer 的自有 `.motorcove` 环境。

## 创建快照

标准备份在维护服务/写入器锁定之前获取共享引导程序所有权。因此，活动引导或恢复在快照工作之前返回 `RESOURCE_BUSY`。仅包含 `seed-journal.json` 和 `bootstrap-receipt.json` 之一的部署快照是不完整的，并且不是可恢复的标准备份。

```bash
pnpm db:backup --env docs-smoke
```

该命令使用 SQLite 备份 API，验证完整性、外键、模式契约和本机历史记录，然后发布包含校验和、源准备情况、恢复策略和投影证据的格式 3 捆绑包。标准备份要求不存在维护标记。它不会复制 Anvil 状态、密钥或钱包日志。

迁移安全和源刷新存档调用在现有维护所有者内部运行。他们必须绑定当前操作ID和目的。它们的捆绑包是 `EVIDENCE_ONLY`：它们保留源检查点、构建、范围、状态、恢复原因以及用于恢复或诊断的标记标识，但正常的恢复命令不会安装它们。

## 显式恢复

恢复在维护锁定之前获取独占引导程序所有权。在隔离之前，它需要活动的 `deployment.json`、`seed-journal.json` 和 `bootstrap-receipt.json` 存在以及字节以匹配已验证的备份。仅数据库恢复会拒绝 sidecar 不匹配，而不是组合两个引导生成。

```bash
pnpm db:restore --env docs-smoke --backup <verified-backup-id> --yes
```

恢复验证源包，将其数据库复制到操作拥有的暂存，并在移动活动文件之前对暂存字节重复清单 SHA-256 检查。然后，它隔离当前的主 DB 和 WAL/SHM sidecar，安装独立快照，使用 WAL 策略打开它，并再次验证。跨验证/复制边界的源更改在隔离之前失败。 `--yes` 确认破坏性选择；它不会绕过所有权或校验和防护。数据库恢复永远不会回滚链。恢复仅接受记录源条件为 `READY` 的 `STANDARD` 快照。

## 恢复中断的操作

```bash
pnpm ops:recover --env docs-smoke
pnpm ops:recover --env docs-smoke --complete
```

第一个命令报告标记。仅当活动、暂存或隔离的候选者成为经过验证的数据库后，`--complete` 才会重新获取锁定并清除标记。切勿将删除 `maintenance.json` 作为正常恢复方法。

标记发布为每次更新使用新的专有临时文件名，然后通过 `maintenance.json` 自动重命名并同步目录。发布的标记具有权威性。如果进程在重命名之前终止，则匹配的恢复会忽略该未发布的文件，并在下次成功发布后删除孤立的临时文件。操作员不得手动升级或删除标记临时文件。

报告命令可以读取没有所有权的标记，因为它只是预览。 `--complete`路径先获取环境维护锁，然后再次读取标记；所有恢复选择和突变都使用该锁拥有的快照。在锁定获取之前观察到的标记永远不会用于清除或完成操作，因为在命令等待时另一个所有者可能已替换它。

SQLite main、WAL、SHM 文件为一代。如果仅移动活动主文件后恢复停止，则恢复会首先将剩余的活动 sidecar 移至同一隔离区，然后再安装暂存的独立快照。如果它从隔离区回滚，它会重新组合该隔离区的主车和边车。活动位置和隔离位置的重复 sidecar 不明确；恢复会停止并保留标记，而不是选择一个。

## 停止条件

出现校验和/身份不匹配、候选缺失、模式漂移、历史分歧或链部署不匹配时停止。保留标记、隔离和报告以供诊断。

临时测试涵盖 WAL 快照、损坏的备份拒绝、验证恢复以及进程终止的热 WAL 文件切换崩溃窗口。硬件断电、恢复后的链前追赶以及所有文件系统故障模式均未验证。

## 源模式备份证据

备份验证完整性、外键、作为存储库迁移包的已知前缀的本机历史记录，以及针对数据库自己的 `db_contract` 行的实时模式指纹。清单记录了快照的实际迁移计数、前缀摘要、架构指纹和源合约版本。它没有将快照描述为已经处于未来的目标模式。

对于迁移前快照，成功发布是一个持久的迁移阶段。迁移标记存储已发布的备份ID，并且每个匹配的恢复在应用SQL之前再次调用普通备份验证器。它还将经过验证的快照证据与实时源数据库和部署身份进行比较。失败的备份不会留下任何证据，因此下一次匹配运行必须重试备份创建。记录证明后的失败将重用相同的经过验证的快照。

恢复当前仅安装与运行代码的目标架构匹配的快照。在移动活动数据库之前，有效的旧快照会失败并显示 `BACKUP_REQUIRES_MIGRATION`；通过迁移工作流程升级它，而不是绕过防护。中断的投影重建或重新索引将保持 `ACTION_REQUIRED`，直到匹配的投影命令完成。

RESET有自己的竣工合约。 `PREPARED`表示链上结果未经证明，返回`ACTION_REQUIRED / RERUN_MATCHING_RESET`；恢复不会检查旧数据库并称其成功。 `CHAIN_RESET` 或 `LOCAL_STATE_CLEARED` 允许恢复在独占引导和维护所有权下完成生成状态删除。备份、受管节点绑定、所有权和稳定锁定文件保留在删除集之外。

## 部署和 sidecar 身份

备份格式 3 记录显式部署状态。 `DEPLOYED` 快照绑定数据库部署 ID 并记录部署、引导接收和种子日志 sidecar 的存在和 SHA-256 证据。 `PREDEPLOYMENT` 快照仅在数据库部署行数为零且所有三个 sidecar 均不存在时才有效。这使得迁移可以保护初始化的预部署数据库，而无需发明链身份。预部署快照中的 sidecar，或者已部署快照中丢失或更改的 sidecar，验证失败。

在创建隔离目录之前，还原会将已部署的备份与活动数据库和活动部署清单进行比较。相同环境名称的早期部署的备份将被拒绝。部署前备份是迁移证据，当前从恢复命令返回 `BACKUP_PREDEPLOYMENT_RESTORE_UNSUPPORTED`；它们不是作为部署环境安装的。

恢复不会安装 sidecar、重置 Anvil、部署合约或重放种子交易。移动整个环境需要一个单独的、明确的工作流程；数据库恢复适用于相同的部署身份，并且可能随后是正常的 Indexer 追赶。

## Bootstrap 收据证据

已部署环境的标准快照需要配对种子日志和可解析的、身份绑定的引导收据。备份会在发布之前验证复制的收据，即使记录的校验和匹配，备份验证也会再次检查其架构和身份。无法通过编辑备份或从其他部署复制收据来修复丢失或格式错误的收据。在进行标准备份之前，通过其拥有的工作流程解决不完整的引导程序。
