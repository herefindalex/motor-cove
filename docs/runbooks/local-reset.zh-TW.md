# 如何重置一次性本地演示

[English](local-reset.md) · [简体中文](local-reset.zh-CN.md)

重置是破壞性本地操作，而不是遷移、種子、重建或復原。

## 保護序列

1. 確認本機模式、環回 RPC、Anvil 用戶端、預期鍊和擁有的環境標記。
2. 解析真實路徑，拒絕符號連結/外部路徑，然後取得引導程式生命週期所有權，
   排他服務門和排他寫入器鎖依此順序排列。
3. 獲取門後，重新運行 `lstat` 和 `realpath` 遏制檢查 `databaseDir` 和
   `reportsDir`。在發布標記或呼叫鏈之前拒絕遺失、非目錄、符號連結或外部子項。
4. 發布 `RESET / PREPARED`，然後呼叫 `anvil_reset`，同時相同的操作擁有這些閘。
5. 發布`CHAIN_RESET`，重新檢查破壞性子路徑，刪除產生的資料庫並
   生命週期 sidecar，發布 `LOCAL_STATE_CLEARED`，然後清除標記。
6. 保留鎖定檔案、備份、來源資產、託管節點綁定和其他工作區。
7. 重新建立一個真正的新部署，然後進行遷移、種子、索引和驗證。

`--yes` 無法繞過任何身分或路徑防護。重置不得殺死未知進程、刪除穩定鎖 inode 或假裝新的清單 ID 是新的鏈上部署。

生命週期所有權和持久的 `PREPARED` 標記都先於 `anvil_reset`。因此，正在部署或等待種子接收的引導程式會在任何鍊或環境突變之前阻止重置。重置在生命週期所有權之前釋放維護鎖定； bootstrap 使用相同的從外到內的順序。

如果復位停止在`PREPARED`，則連鎖結果未知。 `ops:recover --complete` 報告 `ACTION_REQUIRED / RERUN_MATCHING_RESET` 並保留標記和本地狀態。如果marker證明為`CHAIN_RESET`，則recovery完成冪等局部清理；它永遠不會僅僅因為舊資料庫仍然通過模式驗證而清除標記。不要刪除標記或手動將舊的 sidecar 與重置鏈混合。

`MOTORCOVE_ENV=<id> pnpm demo:reset -- --yes` 應用這些防護措施。僅將其用於一次性擁有的環境。自動化 CLI 案例證明，`--yes` 仍然拒絕非環回 RPC URL、鏈 ID 不是 31337 以及不識別為 Anvil 的客戶端。重置覆蓋範圍也保留鎖定索引節點和備份。真實的 `flock` 案例證明，引導程式所有權會阻止 `anvil_reset`，直到所有者退出。子程序 `SIGKILL` 案例證明持久標記先於受控鏈副作用；完整的受管節點整合執行真正的 Anvil 重位，無需故障注入。這些檢查不能證明硬體斷電行為或對環回上模擬 Anvil 的惡意進程的抵抗力。

## 託管節點所有權

每個託管環境都必須具有由 bootstrap 建立的 `managed-node.json` 綁定。此綁定將同一連接埠的 `localhost`、`127.0.0.1` 和 `::1` 標準化為一個節點身分。當綁定遺失、與其他環境衝突或與配置的 RPC 端點不匹配時，Indexer 啟動和重設將拒絕繼續。

Reset 在呼叫 `anvil_reset` 之前驗證此所有權。它保留綁定，同時刪除產生的資料庫、部署、引導、種子和報告狀態。為每個受管環境啟動單獨的本機 Anvil 端點；僅變更主機名稱別名不會建立單獨的節點。

鎖定後子路徑檢查縮小了初始環境所有權驗證和破壞性使用之間的差距。如果另一個程序以符號連結取代任一產生的目錄，則重設會在鏈回呼之前停止，並保留外部目標和新維護標記的缺失。
