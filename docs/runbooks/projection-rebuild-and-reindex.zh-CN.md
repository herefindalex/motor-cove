# 如何选择重建或重新索引

[English](projection-rebuild-and-reindex.md) · [繁體中文](projection-rebuild-and-reindex.zh-TW.md)

停止 API 和 Indexer 并确定正常追赶无法继续的原因后，使用此 Runbook。

## 选择来源

- **重建** 仅当本地标头/原始日志完整、内容经过验证、范围正确且
  锚定。在一个维护版本中删除/重新创建派生的投影行，同时保留目录。
- 当历史记录、规范分支、解码器范围或日志完整性受到怀疑时，**重新索引**。获取
  来自已验证部署的 RPC 的标头和原始日志，然后重建。
- **新部署** 当部署 getter、代码哈希或清单标识发生更改时。不治疗它
  作为普通的重组。

## 命令

```bash
MOTORCOVE_ENV=<id> pnpm ops:rebuild
MOTORCOVE_ENV=<id> pnpm ops:reindex -- --yes
```

重建将经过验证的本地源证据重播到新的投影版本中。重新索引验证环回部署身份，从请求的块倒回，保留移位的源证据，重新获取规范标头和日志，并捕获捕获的目标。

## 成功条件

成功需要一个新的 `projectionBuildId`、保留的目录/绑定、按规范顺序重播所有适用的源事件、到达经过验证的检查点以及同一块/哈希上的对账。故障不得暴露半成品投影。

请参见[索引流程](../flows/indexing-and-recovery.zh-CN.md) 和 [对账](reconciliation.zh-CN.md)。

## 恢复中断的操作

使用 `pnpm ops:recover --env <id>` 检查标记。对于`REBUILD_PROJECTION`和`REINDEX_PROJECTION`，`--complete`有意返回`ACTION_REQUIRED`；它不会清除标记。停止运行时并重新运行相同的重建命令，或使用原始 `--from` 值重新运行相同的重新索引命令。恢复需要匹配操作类型、部署、回滚点、捕获的目标块和目标哈希。恢复的命令验证并重用标记的原始目标；当活头前进时，它不会移动目标。丢失或更改的目标锚点在再次倒回之前仍处于锁定状态。

## 源预检和维护兼容性

在重建更改投影行之前，它会验证从部署扫描开始到检查点的连续规范和扫描完成标头。每个块的观察计数和摘要必须与存储的事件行匹配，并且每个事件必须保留其原始信封、解码事件和解码器版本绑定。 `REBUILD_SOURCE_INCOMPLETE` 保留现有的投影；使用重新索引重新获取源而不是编辑日志行。

具有该确切错误的失败重建可能会在同一独占维护门下转换为完整重新索引。重新索引必须从部署扫描开始块开始，捕获并验证目标块/哈希，并匹配标记的环境、数据库、部署和架构契约。新标记接收新的操作 ID 并将失败的重建操作 ID、类型和错误记录为沿袭。其他失败的重建原因、部分重新索引范围和隐式标记更改仍然被阻止。

Reindex 捕获 `head - indexingDepth` 及其哈希值作为完成目标。非零深度不会等待不合格的活头，闲置链不需要额外的交易来完成。如果目标哈希在捕获时发生更改，则重新索引会在维护倒回之前停止。

如果操作员在数据库已经投影更新的块后增加索引深度，则正常摄取会停止并显示 `CHECKPOINT_EXCEEDS_ELIGIBLE_TARGET`。从部署扫描开始运行重新索引，以便其固定的合格目标和重建的投影强制执行新的保留。请勿清除恢复原因或手动降低检查点。减少深度不需要重建并且可以正常地向前赶上。

运行时启动拒绝投影器或日志范围不匹配。维护仅接受明确支持的先前投影器版本。仅当重新索引在部署扫描开始块开始时才允许范围更改。

## 源刷新归档边界

当受支持的范围、解码器或源-摘要转换需要替换存储的标头和事件时，重新索引会在现有的独占维护门下创建并验证环境备份。在删除活动源行之前，它会将经过验证的备份 ID 写入重新索引标记。中断的恢复会再次验证记录的备份。如果备份创建、校验和验证或标记持久性失败，活动源日志保持不变。

备份保留先前的 SQLite 源行，包括移位的或孤立的证据。重新索引仍然仅重新获取活动构建所需的规范范围；备份是诊断和恢复证据，而不是 RPC 可以重现历史孤立日志的承诺。

在重新索引准备之前立即评估源刷新分类。当非空事件行的原始信封、解码的有效负载、解码器版本、源记录摘要或已完成块的相同计数摘要不一致时，需要刷新。重新索引必须从部署扫描开始块开始，记录并验证备份，然后重新获取规范源。纯粹的缺失事件行遵循普通的倒带和重新插入，而不是被错误地标记为矛盾的内容。 `EVENT_IDENTITY_CONTENT_MISMATCH` 在正常摄取期间仍然是硬故障。

## 验证源快照身份

正常的追赶和重新索引在日志之前获取标头，然后使用精确观察到的块哈希值请求日志。合规的链提供商必须支持 EIP-234 区块哈希日志过滤器。 MotorCove 不会将数字范围内的日志与该请求后观察到的标头结合起来。

当诊断显示标头/日志身份错误时：

1. 保留当前检查点和维护标记。
2. 确认配置的 RPC 可以通过块哈希为部署范围提供日志。
3. 传输运行状况恢复后，重新运行相同的重新索引操作。
4. 不要编辑扫描完成的元数据或源行来强制进度。

为本地 Indexer 传输启用了 JSON-RPC 批处理，因此每个标头身份检查不会将较大的追赶范围转变为序列化的 HTTP 往返。

## 恢复长时间重建索引

重新索引可能需要超过 1,000 个成功批次。该命令将运行直到达到其固定的合格目标，前提是每次成功的迭代都会推进持久检查点。

标记的`projectionPhase`决定安全恢复：

- `PREPARING`：该操作仍可以执行其拥有的源倒带和投影准备。
- `CATCHING_UP`：使用相同的 `--from` 值重新运行相同的命令。它重建派生的投影
  从保留的源证据中陈述并从检查点继续，而不会再次倒回。

`REINDEX_CATCHUP_NO_PROGRESS` 表示适配器成功返回，但没有推进持久状态。保留标记，检查检查点和提供商响应，然后仅在纠正原因后恢复。不要清除标记或启动新目标来绕过此错误。

## 持续恢复原因

不要使用重建来清除规范或源完整性原因，例如检查点哈希更改、父级不连续性、日志块哈希不匹配或高于合格索引目标的检查点。维护命令在更改其标记之前拒绝该操作。使用显式重新索引路径。 投影器-only完整性可以在本地原始源通过验证后使用重建。失败的重建索引保留其标记和恢复要求；恢复匹配操作而不是启动运行时编写器。已完成的固定重新索引目标进入 `SYNCING`，直到实时合格的头部观察支持 `CURRENT`。
