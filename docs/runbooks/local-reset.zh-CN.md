# 如何重置一次性本地演示

[English](local-reset.md) · [繁體中文](local-reset.zh-TW.md)

重置是破坏性本地操作，而不是迁移、种子、重建或恢复。

## 保护序列

1. 确认本地模式、环回 RPC、Anvil 客户端、预期链和拥有的环境标记。
2. 解析真实路径，拒绝符号链接/外部路径，然后获取引导程序生命周期所有权，
   排他服务门和排他写入器锁按此顺序排列。
3. 获取门后，重新运行 `lstat` 和 `realpath` 遏制检查 `databaseDir` 和
   `reportsDir`。在发布标记或调用链之前拒绝丢失、非目录、符号链接或外部子项。
4. 发布 `RESET / PREPARED`，然后调用 `anvil_reset`，同时相同的操作拥有这些门。
5. 发布`CHAIN_RESET`，重新检查破坏性子路径，删除生成的数据库并
   生命周期 sidecar，发布 `LOCAL_STATE_CLEARED`，然后清除标记。
6. 保留锁定文件、备份、源资产、托管节点绑定和其他工作区。
7. 重新创建一个真正的新部署，然后对其进行迁移、种子、索引和验证。

`--yes` 无法绕过任何身份或路径防护。重置不得杀死未知进程、删除稳定锁 inode 或假装新的清单 ID 是新的链上部署。

生命周期所有权和持久的 `PREPARED` 标记都先于 `anvil_reset`。因此，正在部署或等待种子接收的引导程序会在任何链或环境突变之前阻止重置。重置在生命周期所有权之前释放维护锁； bootstrap 使用相同的从外到内的顺序。

如果复位停止在`PREPARED`，则连锁结果未知。 `ops:recover --complete` 报告 `ACTION_REQUIRED / RERUN_MATCHING_RESET` 并保留标记和本地状态。如果marker证明为`CHAIN_RESET`，则recovery完成幂等局部清理；它永远不会仅仅因为旧数据库仍然通过模式验证而清除标记。不要删除标记或手动将旧的 sidecar 与重置链混合。

`MOTORCOVE_ENV=<id> pnpm demo:reset -- --yes` 应用这些防护措施。仅将其用于一次性拥有的环境。自动化 CLI 案例证明，`--yes` 仍然拒绝非环回 RPC URL、链 ID 不是 31337 以及不识别为 Anvil 的客户端。重置覆盖范围还保留锁定索引节点和备份。真实的 `flock` 案例证明，引导程序所有权会阻止 `anvil_reset`，直到所有者退出。子进程 `SIGKILL` 案例证明持久标记先于受控链副作用；完整的受管节点集成执行真正的 Anvil 复位，无需故障注入。这些检查不能证明硬件断电行为或对环回上模拟 Anvil 的恶意进程的抵抗力。

## 托管节点所有权

每个托管环境都必须具有由 bootstrap 创建的 `managed-node.json` 绑定。该绑定将同一端口的 `localhost`、`127.0.0.1` 和 `::1` 标准化为一个节点身份。当绑定丢失、与其他环境冲突或与配置的 RPC 端点不匹配时，Indexer 启动和重置将拒绝继续。

Reset 在调用 `anvil_reset` 之前验证此所有权。它保留绑定，同时删除生成的数据库、部署、引导、种子和报告状态。为每个受管环境启动单独的本地 Anvil 端点；仅更改主机名别名不会创建单独的节点。

锁定后子路径检查缩小了初始环境所有权验证和破坏性使用之间的差距。如果另一个进程用符号链接替换任一生成的目录，则重置会在链回调之前停止，并保留外部目标和新维护标记的缺失。
