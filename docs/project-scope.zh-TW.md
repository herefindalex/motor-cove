# 專案範圍

[English](project-scope.md) · [简体中文](project-scope.zh-CN.md)

此頁面定義了 MotorCove 演示的內容及其聲明的停止位置。

## 範圍內

原始碼定義 Anvil（`31337`）、Ethereum（`1`）與 Polygon（`137`）鏈設定檔。公鏈設定檔要求提供者支援
finalized 區塊，營運者可用另一個獨立設定的提供者比對已最終確定的來源證據。賣方在託管銷售中為每筆
銷售指定一位買方。這些是實作契約；尚未執行公網部署或 RPC 驗證。

MotorCove 為本地測試資產建模了一個狹窄的 ERC-721 市場。產品表麵包括注入錢包流程、批准和託管清單、確切價格融資、完成或到期、基於拉取的收益和退款、NFT 回收、事件派生的讀取模型、只讀查詢 API 和本地資料庫生命週期工具。

工程範圍包括強制模組邊界、產生的 ABI 和 HTTP 合約、部署身分、持久事務觀察、替換和重組分類、重播/重建/重新索引/對帳、遷移歷史、維護協調、本地 CI 門和貢獻者切換。

## 驗證本地恢復邊界

- 一次真實的 Anvil 廣播後丟失的錢包回應可以透過提供重新加載後恢復
  交易哈希。恢復是唯讀的，不會再提交。
- 相同隨機數替換分為 `REPRICED`、`CANCELLED` 或 `DIFFERENT_CALL`。
  孤立的收據證據變為 `NONCANONICAL`，並且相同雜湊重新包含記錄新的規範收據和事件身分。
- 真實的SQLite案例涵蓋本機遷移歷史和失敗回滾，鎖定所有者`SIGKILL`，
  受控 `SQLITE_BUSY`、有界 `SQLITE_FULL`、重播、重建、規範重新索引、實時頭後面的備份還原以及單快照 API 讀取。
- 當其部署標識已被拒絕時，重複使用確定性合約位址的重置將被拒絕。
  改變了。重置CLI拒絕非環回RPC、錯誤的鏈ID和非Anvil客戶端。
- 對帳使用錨定的 `saleCount` 和 `nextTokenId` 來偵測完全缺失的銷售並
  每個鑄造代幣的所有權行。

## 目前的實施或驗證差距

- 鏈廣播到哈希日誌視窗中的真實進程終止不會被注入。確定性
  日誌測試證明了已知哈希恢復和圍繞該邊界的保守 `UNKNOWN` 行為。
- 第一次架構升級具有保留資料 `0000` 到 `0001` 固定裝置。相容性
  儲存庫記錄的遷移歷史之外的架構仍未得到驗證和支援。
- 受控 SQLite 頁面耗盡證明原子回滾，但不模擬完整主機
  文件系統。 `SIGKILL` 不證明控制器快取、檔案系統刷新或硬體斷電耐久性。
- 手動 MetaMask 提示和提供者特定的行為未經驗證。瀏覽器自動化使用
  受控 EIP-1193 適配器。
- GitHub Actions 運行是特定於提交的，並且與本地證據分開記錄。分公司
  保護、所需審閱設定和儲存庫審閱者身分仍然需要擁有者配置且仍未驗證。

## 非目標

- 實體車輛所有權、交付、融資、稅務或法定所有權。
- 主網或公共測試網部署、真實貨幣或有價值的資產。
- 後端身份驗證、SIWE、錢包託管、金鑰管理或自動簽署。
- 生產資料庫服務、跨主機SQLite、線上遷移或零停機復原。
- 自動修復每個鏈不匹配、通用公共網路重組策略或恰好一次
  鍊式交易。
- 外部安全審計、生產負載測試、團隊速度或實際團隊使用的聲明。

## 安全邊界

只有環回 Anvil、鏈 ID `31337`、合成帳戶、測試 ETH 和測試資產屬於演示工作流程。維護命令需要 `.motorcove/environments/<id>` 下的自有環境，且不得指向任意資料庫。僅使用具有一次性環境 ID 的破壞性演示命令。預先存在的 `data/motorcove.sqlite` 檔案位於託管路徑之外，並且永遠不會自動採用或重置。
