# ADR 0005：唯讀交易復原與快照收斂

[English](0005-transaction-convergence.md) · [简体中文](0005-transaction-convergence.zh-CN.md)

- **狀態：**已接受
- **範圍：** `SALE-002`、瀏覽器日誌恢復、資金觀察、Indexer提交故障

## 背景

錢包哈希、成功收據、索引事件和預計的 Sale 在不同時間變得可見。任何間隙期間的重新加載都必須透過讀取證據來恢復，而無需重複付款。僅比較檢查點高度或組合來自不同 SQLite 時刻的行也可能產生錯誤的完成結果。

## 決定

在調用錢包之前保留不可變的資金意圖和錢包請求邊界。將提交保留在專用的申請功能中。 Recovery只有鏈讀取、API讀取和日誌連接埠；架構檢查拒絕錢包寫入相依性。

使用全有或全無事件選擇器擴展現有銷售 GET 路由。資料庫讀取器從一次讀取事務中傳回覆蓋範圍、請求高度規格標頭、事件查找、投影效果、新鮮度和來源。一致的資金效應接受 `FUNDED`、`COMPLETED` 或 `EXPIRED`，並且不需要付款索賠。

保留現有的Indexer交易邊界。僅測試同步故障鉤子為子進程 `SIGKILL` 測試提供精確的 pre-BEGIN、pre-COMMIT 和 post-COMMIT 進程障礙。

為每個非同步驗證指派一個產生 ID，並僅在該產生保持目前狀態時將其結果合併到最新儲存的日誌條目中。隨機數豐富也會重新載入最新條目並僅更改隨機數。使用一個選擇器定義目前的投影成功，該選擇器需要包含成功、成功收據和反映的投影。

## 後果

- 重新載入、輪詢、候選哈希驗證和投影重試無法提交交易。
- 遺失的雜湊仍然可操作 `UNKNOWN`；使用者介面從未將其他付款描述為安全的。
- 成功的鏈執行和投影收斂仍然是獨立的用戶可見事實。
- 相同隨機數替換被分類為重新定價、取消或任何先前的不同調用
  更換收據即可滿足原意。
- 孤立的收據證據仍然可見，為 `NONCANONICAL`；相同哈希重新包含必須建立
  新的規範收據和事件識別。
- 緩慢的驗證或隨機數字查找無法取代較新的收據或投影證據。
- 選擇器請求不能改變 Indexer 運作狀況或資料庫狀態。
- WAL 進程終止證據與正常回滾和硬體斷電分開記錄。
