# ADR 0004：停止不明确的链种子结果

[English](0004-chain-seed-ambiguity.md) · [繁體中文](0004-chain-seed-ambiguity.zh-TW.md)

## 状态

已接受。

## 背景

本地引导程序发送非幂等合约部署、铸造、批准和列出交易。在 RPC 节点接受交易之后但在调用者持久记录其哈希之前，进程可以停止。再次发送相同的逻辑步骤可以创建另一个合约、铸造另一个代币或开启另一个销售。 EVM 交易不提供应用程序级的一次性保证。

## 决定

Bootstrap 使用一个环境拥有的 `seed-journal.json` 并将其绑定到每个逻辑步骤的环境、链 ID、发送者帐户、部署 ID 和不可变意图摘要。

- 在要求钱包客户端提交之前坚持`PREPARED`。
- 在等待收据之前，将返回的交易哈希保留为 `SUBMITTED`。
- 成功收货后才标记`VERIFIED`。
- 重新运行时，使用已知的提交哈希并重新验证经过验证的收据，而无需再次提交。
- 将搁浅的 `PREPARED` 步骤或结果未知的提交调用视为 `UNKNOWN` 并停止。
- 拒绝身份变更、意图变更和已验证收据证据的变更。
- 一旦部署清单存在，验证其链身份并执行数据库追赶，而无需
  发送种子交易。

操作员在调查时保留日志。返回到新的演示状态使用一次性拥有环境的受保护重置工作流程。

## 后果

常见的重试路径是确定性的，完成的引导不会覆盖以后的用户操作。不明确的广播可能需要手动证据审查或明确重置。该设计并不要求一次性链交易，并且广播到哈希持久性窗口中的真正进程终止仍然是单独的故障注入测试。
