# ADR 0019：维护标记发布和快照准备情况

[English](0019-maintenance-marker-and-snapshot-readiness.md) · [繁體中文](0019-maintenance-marker-and-snapshot-readiness.zh-TW.md)

- **状态：**已接受
- **日期：** 2026-09-22

## 背景

维护状态存在于 SQLite 之外，因为它必须在进程终止后阻止运行时启动。标记写入器之前为操作中的每次更新重复使用一个临时文件名。在刷新临时文件之后但在重命名之前，进程被终止，该文件名被占用，因此相同的操作在重试时永远无法发布 `ACTIVE` 或 `FAILED`。

SQLite备份还证明了数据库完整性和部署身份，而无需记录源是否在未完成的维护中。因此，在重新索引阶段之间拍摄的一致快照可以在其外部标记消失后通过备份验证，即使它代表诊断证据而不是正常的服务就绪还原点。

## 决定

1. 每个标记更新都使用新的专有临时文件名。已发表的
   `maintenance.json` 保持唯一提交的操作状态。成功的原子替换后，拥有锁的编写器将删除同一操作的孤立临时文件。失败的重命名会尽可能删除其自己的临时文件，并保留原始文件系统错误。
2. 当任何维护标记存在时，标准备份将拒绝运行。内部迁移安全
   源刷新归档调用必须提供当前操作 ID 和与持久标记匹配的固定用途。
3. 备份格式3记录`sourceCondition`、`restorePolicy`和投影证据
   快照。维护源生成包含操作标识、标记摘要、阶段、目的和投影阶段的 `EVIDENCE_ONLY` 存档。检查点、构建、范围、投影状态和恢复原因在验证期间从数据库重新计算。
4. 普通恢复命令仅接受从不包含任何内容的源创建的 `STANDARD` 快照。
   维护标记。仅证据存档仍可用于需要它们的操作和诊断，但不能通过成为普通恢复来静默删除运行时门。

## 后果

- 被杀死的标记发布不能将其他匹配的维护简历搁置在 `EEXIST` 上。
- 正式标记具有权威性；未发布的临时字节永远不会提前操作状态。
- 迁移和源刷新保留经过验证的备份证据，无需提供中间内容
  投影已做好服务准备。
- 较旧的备份格式在当前验证程序下无法关闭。该项目没有发布备份
  兼容性合约；保留的内部证据必须用创建它的代码来解释。

## 验证

- `tests/database/projection-maintenance.test.ts` 在冲掉旧的之后杀死了一个真正的孩子
  固定名称临时标记并验证匹配操作恰好恢复一次。
- `tests/recovery/backup-restore.test.ts` 验证不完整标记下的标准备份拒绝，
  维护证据分类，投影证据验证，恢复隔离前的拒绝。
- 迁移、数据库、恢复和 Indexer 集成门运用现有的内部备份
  调用者及其显式操作上下文。
