# ADR 0012：可恢复维护和日志修订

[English](0012-resumable-maintenance-and-journal-revisions.md) · [繁體中文](0012-resumable-maintenance-and-journal-revisions.zh-TW.md)

- 状态：已接受
- 日期：2026-09-22

## 背景

投影维护和浏览器事务提交都跨越持久边界。重新索引可能会在记录其目标后停止，并且浏览器可能会等待另一个选项卡，然后才能保留意图或返回的哈希值。在恢复上重新计算重新索引目标、删除没有存档的源证据或将挂钟时间视为写入版本会使持久记录与实际运行的操作不一致。

## 决定

1. 新的重新索引一次捕获合格的目标块和哈希值。恢复的重建索引显示
   目标来自其匹配的维护标记，验证相同的块和哈希两次，即使链头前进，也保留原始目标。更改后的目标锚点无法关闭。
2. 维护锁在获得后立即进入其清理范围。标记解析，
   身份检查、恢复解析、模式验证、数据库打开和操作回调都会在失败时释放相同的锁。
3. 源刷新重新索引在删除之前创建并验证正常环境备份
   活动标题或事件。验证后的备份ID首先写入维护标记。恢复验证相同的备份。如果无法创建或验证它，则活动源证据不会受到影响。
4. 每个浏览器日志条目都带有每个操作的修订版本。写入比较其预期
   修订并将其升级到现有的部署 Web Lock 中。不匹配返回 `JOURNAL_REVISION_CONFLICT`； `updatedAt`保留显示证据并且从不决定写入顺序。如果钱包返回的哈希值与较新的无哈希恢复版本竞争相同的不可变意图，则提交会将哈希值合并到最新版本中。不同的意图或哈希仍然是冲突，并回退到显式的非持久处理。
5. 在等待 `AWAITING_WALLET` 后提交重新检查完整的实时操作上下文
   在调用钱包之前立即写入和 。

## 后果

- 操作员可以在执行命令后使用原始 `--from` 值重新运行记录的重新索引命令。
  无需追逐移动的头部即可中断。
- 源刷新备份保留了用于诊断的规范和移位的原始证据，但它们不
  将本地备份转为公共存档 - RPC 可用性。
- 过时的浏览器工作无法报告被默默丢弃的持久更新。来电者必须携带
  转发 `save()` 返回的条目，以便下一次写入使用保留的修订版本。
- 当另一个操作写入时，易失性覆盖不会删除其先前的持久意图
  共享部署日志。
- Web 锁定一个浏览器配置文件中的边界坐标选项卡。它不协调设备，
  并且易失性哈希仍然无法在真正的文档重新加载后幸存下来。

## 验证

单元和集成测试涵盖固定目标恢复、更改锚点拒绝、格式错误和不匹配的标记清理、刷新前备份保存、持久化后上下文失效、挂钟回滚、修订冲突处理和事务恢复。真正的 Chromium 多选项卡测试涵盖并发编写器、过时修订拒绝和编写器选项卡切换。
