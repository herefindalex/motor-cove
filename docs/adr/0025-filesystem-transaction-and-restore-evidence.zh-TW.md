# ADR 0025：檔案系統、交易和恢復證據邊界

[English](0025-filesystem-transaction-and-restore-evidence.md) · [简体中文](0025-filesystem-transaction-and-restore-evidence.zh-CN.md)

- 狀態：已接受
- 日期：2026-09-23

## 背景

三個恢復邊界取決於早期檢查後可能發生變化的證據。

Reset 在採取維護鎖定之前驗證了擁有的環境，然後使用資料庫和報表目錄進行破壞性清理。在所有權檢查之後，進程可以用符號連結取代任一子進程。復原驗證了備份校驗和，然後將來源複製到暫存中，而無需證明暫存位元組是經過驗證的世代。交易恢復將明確遺失的隨機數支援的原始哈希視為一般的 RPC 故障，因此該介面不會告訴操作員需要當前或替換的錢包哈希。

## 決定

重置會在採取維護閘門之後以及產生狀態刪除之前再次重新驗證 `databaseDir` 和 `reportsDir`。每個路徑必須存在，是目錄，而不是符號鏈接，並且在真實環境根目錄內解析。鏈回調和標記發布僅在鎖定後檢查之後發生。

復原會像先前一樣驗證所選備份，將其資料庫複製到作業擁有的暫存，並在隔離活動產生之前根據清單對暫存位元組進行雜湊。架構和部署檢查仍然適用於相同暫存檔案。

只有當日誌具有隨機數、沒有記錄的收據區塊並且檢查的雜湊是其保存的當前或原始雜湊時，交易檢查才會將明確未找到回應分類為 `REPLACEMENT_HASH_REQUIRED`。恢復會保留該分類並要求提供錢包活動哈希。候選人驗證保持只讀狀態，並保留不可變的意圖和原始哈希。

## 後果

- 所有權後符號連結替換無法重定向重置清理或到達鏈回調。
- 在驗證和複製之間變化的備份來源無法取代活動資料庫。
- 當錢包更換或遺失已知的錢包時，操作員會收到精確的恢復操作
  隨機數字支援的交易。
- 通用 RPC 故障仍然无法获得观察证据，并不意味着需要更换。
- 這些決定都沒有授權自動事務重新提交、環境重置或
  邊車更換。

## 驗證

- `DB-74` 用外部符號連結替換每個破壞性重置子項並證明零鏈調用，
  無標記，並保留外部位元組。
- `DB-75` 在複製邊界更改備份來源並證明先前的校驗和拒絕
  隔離，同時活動資料庫保持可讀。
- `TX-009` 涵蓋了鏈檢查、日誌持久性以及經過驗證的觀察者提示
  當前或替換哈希，無需錢包寫入。
