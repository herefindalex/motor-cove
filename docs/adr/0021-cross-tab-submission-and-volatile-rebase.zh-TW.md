# ADR 0021：交叉表提交所有權和易失性證據變基

[English](0021-cross-tab-submission-and-volatile-rebase.md) · [简体中文](0021-cross-tab-submission-and-volatile-rebase.zh-CN.md)

- **狀態：**已接受
- **日期：** 2026-09-22

## 背景

交易功能之前將相同意圖的提交所有權保留在模組級 `Set` 中。這停止了一個 JavaScript 領域中的重複操作，但兩個選項卡都可以保留相同的不可變意圖，模擬它並打開錢包請求。

在錢包返回本地儲存無法保存的雜湊值後，存在單獨的恢復邊緣。此選項卡在其易失性覆蓋層中保留了該哈希值。如果另一個選項卡將相同的持久性條目推進到無雜湊修訂版，則以後的每次持久性重試都會與過時的基本修訂版進行比較並失敗。當前標籤繼續顯示哈希，而重新載入則傳回無哈希持久行。

## 決定

1. 瀏覽器提交使用由完全不可變意圖鍵入的排他 Web 鎖定。所有權
   在第一個日誌寫入或其他等待步驟之前開始，並透過模擬、錢包互動、返回哈希持久性和可選的隨機數豐富保持不變。
2. 繁忙的相同意圖激活在創建一個之前失敗並顯示 `OPERATION_ALREADY_IN_FLIGHT`
   日誌輸入、模擬或開啟錢包請求。不同的不可變意圖使用不同的鎖並保持並發。
3. 沒有 Web Locks 的瀏覽器保留現有的模組級回退。後備座標
   僅在一個 JavaScript 領域中的呼叫者，並且不提供跨表所有權。
4. 易失性的持久性重試可能會改變新的持久性修訂版上唯一的交易證據
   僅當兩行描述相同的客戶端操作、不可變意圖和錢包請求，且持久行沒有交易證據時。持久修訂是從當前持久修訂前進的。
5. 如果持久行已包含雜湊、收據、關聯、投影證明或其他
   交易證據，重試失敗關閉。它永遠不會猜測哪個證據獲勝，也永遠不會打開另一個錢包請求。

## 後果

- 具有 Web Locks 的一個瀏覽器設定檔最多可開啟一個同時啟動的錢包請求
  跨選項卡的不可變意圖。
- 關閉擁有者標籤會在瀏覽器生命週期中釋放其 Web Lock。然後另一個選項卡可能會
  取得所有權並且必須開始新的明確操作，而不是繼承未知的記憶體中回呼。
- 在並發無哈希恢復修訂後，返回的哈希可以變得持久，而無需擦除
  該修訂版的不可變上下文。
- 沒有 Web Locks 的跨裝置協調和跨選項卡協調仍然在範圍之外
  保證。在升級成功之前，僅易失性證據仍然無法在重新加載後倖存。

## 驗證

- `submit-operation.test.ts` 證明在日誌創建、模擬和之前被拒絕的所有權
  錢包提交。
- `browser-submission-coordinator.test.ts` 涵蓋同意圖排除、獨立金鑰和鎖
  成功或失敗後釋放。
- `local-storage-journal.test.ts` 涵蓋了並發無哈希修訂上的安全哈希變基，以及
  拒絕覆蓋有衝突的持久交易證據。
- `journal-multitab.spec.ts`使用兩個真實的Chromium頁面來驗證跨表提交排除，
  一個錢包請求、獨立意圖、正常釋放和所有者關閉切換。
