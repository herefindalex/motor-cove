# ADR 0007：序列化恢复证据并对运行时链故障进行分类

[English](0007-concurrent-recovery-evidence.md) · [繁體中文](0007-concurrent-recovery-evidence.zh-TW.md)

- **状态：** 在本地运行时接受并实施
- **范围：** 投影维护、Indexer轮询、浏览器交易验证

## 背景

投影重新索引重用持久块和事件，浏览器验证可以与随机数丰富或其他验证请求重叠，并且 JSON-RPC 错误并不都意味着同一件事。在每种情况下，将旧的或不可用的观察结果视为当前事实可能会擦除新的证据或将操作员送入错误的恢复程序。

## 决定

重建和重新索引在专有维护门下运行。它们在更改投影状态之前保留 `PREPARED` 和 `ACTIVE` 标记，在出错时保留 `FAILED` 标记，并仅在成功后清除标记。重新索引可以重新规范化现有块并将其已存储的事件重新应用到新的投影。每个新批次都会在提交之前验证其第一个父哈希是否加入了持久检查点。

浏览器验证为每个请求分配一个生成 ID，并在保存之前重新加载最新的日志条目。仅当其生成保持最新时，结果才能更新日志。可选的随机数丰富仅将随机数合并到最新条目中。 UI从交易状态、收货状态和投影观察共同得出当前投影成功；历史接收证据可以在重组后保留，而不会呈现为当前的成功。

Indexer 将传输超时和连接失败归类为临时不可用。它保留检查点，标记投影新鲜度 `STALE`，以有界指数退避重试，并让 API 和 Web 进程继续。更改的检查点哈希、提供者确认的丢失检查点块或其他完整性不匹配仍然是 `RECOVERY_REQUIRED` 并停止摄取。关闭会停止调度轮询，等待活动轮询，然后关闭数据库写入器。

### 特定于操作的完成

中断的投影标记携带其部署和恢复标识。通用恢复不会将模式完整性视为回滚、重建和追赶已完成的证据。它返回所需的操作并关闭大门。重新运行确切的操作可能会恢复同一锁下的标记；更改的参数被拒绝。

目前投影的成功与交易哈希、区块哈希、日志索引、部署和投影构建息息相关。如果无法持久保存返回的事务哈希，则哈希和操作上下文在选项卡本地日志覆盖中保持可见，并具有显式重新加载限制。此覆盖不具有持久性或跨设备恢复能力。

## 权衡

- 浏览器生成检查坐标保存的日志证据但不提供跨设备
  分布式事务。
- 错误地将历史块报告为丢失的提供者仍然可以要求操作员
  恢复；超时或连接错误不会。
- 维护仍然是一台受信任主机上的显式停机操作。
- 退避保持过时的读取可用，同时将后续重试尝试延迟最多八次
  秒。

## 后果

当前的有效性和历史证据仍然是分开的。 投影维护无法向普通读取器或写入器公开中间版本。本地进程管理程序不会仅仅因为 Indexer 退出而终止 API 和 Web，并且优雅的 Indexer 停止不会在活动轮询下关闭 SQLite。
