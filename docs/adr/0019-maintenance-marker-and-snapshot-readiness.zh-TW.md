# ADR 0019：維護標記發布和快照準備情況

[English](0019-maintenance-marker-and-snapshot-readiness.md) · [简体中文](0019-maintenance-marker-and-snapshot-readiness.zh-CN.md)

- **狀態：**已接受
- **日期：** 2026-09-22

## 背景

維護狀態存在於 SQLite 之外，因為它必須在進程終止後阻止運行時啟動。標記寫入器之前為操作中的每次更新重複使用一個臨時檔案名稱。在刷新臨時檔案之後但在重新命名之前，進程被終止，該檔案名稱被佔用，因此相同的操作在重試時永遠無法發布 `ACTIVE` 或 `FAILED`。

SQLite備份也證明了資料庫完整性和部署身份，而無需記錄來源是否在未完成的維護中。因此，在重新索引階段之間拍攝的一致快照可以在其外部標記消失後通過備份驗證，即使它代表診斷證據而不是正常的服務就緒還原點。

## 決定

1. 每個標記更新都使用新的專有臨時檔案名稱。已發表的
   `maintenance.json` 保持唯一提交的操作狀態。成功的原子替換後，擁有鎖的編寫器將刪除相同操作的孤立臨時檔案。失敗的重命名會盡可能刪除自己的臨時文件，並保留原始檔案系統錯誤。
2. 當任何維護標記存在時，標準備份將拒絕運作。內部遷移安全
   來源刷新歸檔呼叫必須提供目前操作 ID 和與持久標記相符的固定用途。
3. 備份格式3記錄`sourceCondition`、`restorePolicy`和投影證據
   快照。維護來源產生包含操作標識、標記摘要、階段、目的和投影階段的 `EVIDENCE_ONLY` 檔案。檢查點、建置、範圍、投影狀態和復原原因在驗證期間從資料庫重新計算。
4. 普通復原指令僅接受從不包含任何內容的來源所建立的 `STANDARD` 快照。
   維護標記。僅證據存檔仍可用於需要它們的操作和診斷，但不能透過成為普通恢復來靜默刪除執行時門。

## 後果

- 被殺死的標記發布不能將其他匹配的維護簡歷擱置在 `EEXIST` 上。
- 正式標記具有權威性；未發布的臨時位元組永遠不會提前操作狀態。
- 遷移和來源刷新保留經過驗證的備份證據，無需提供中間內容
  投影已做好服務準備。
- 較舊的備份格式在目前驗證程序下無法關閉。該項目沒有發布備份
  相容性合約；保留的內部證據必須用創建它的程式碼來解釋。

## 驗證

- `tests/database/projection-maintenance.test.ts` 在沖掉舊的之後殺死了一個真正的孩子
  固定名稱臨時標記並驗證匹配操作恰好恢復一次。
- `tests/recovery/backup-restore.test.ts` 驗證不完整標記下的標準備份拒絕，
  維護證據分類，投影證據驗證，恢復隔離前的拒絕。
- 遷移、資料庫、復原和 Indexer 整合閘運用現有的內部備份
  呼叫者及其顯式操作上下文。
