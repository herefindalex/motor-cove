# ADR 0022：引导快照边界和对账发布新鲜度

[English](0022-bootstrap-snapshots-and-reconciliation-publication.md) · [繁體中文](0022-bootstrap-snapshots-and-reconciliation-publication.zh-TW.md)

- **状态：**已接受
- **日期：** 2026-09-22

## 背景

Bootstrap拥有链部署、种子交易、数据库注册、目录数据、投影追赶及其完成收据。它的独占生命周期锁与备份和恢复使用的服务锁和写入器锁是分开的。因此，标准备份可以在注册之后但引导程序完成之前复制已部署的数据库。后来恢复旧的数据库留下了新的种子日志和引导收据，发布了混合生成。

对账比较投影和一个检查点区块和哈希的链状态。它在可能的长时间比较之前对最新的头部进行了采样，并在发布新鲜度时重复使用了该样本。因此，在比较过程中前进的头部可以报告为 `CURRENT`。

## 决定

1. 标准备份在维护锁定之前获取共享引导程序所有权。恢复获取
   维护锁定之前的独占引导程序所有权。活动引导、恢复和标准快照工作不能在一个托管环境中重叠。
2. 迁移安全备份可以明确地重用生产已经拥有的引导程序所有权
   引导调用者。这可以避免重新获取不可重入生命周期锁，同时保留相同的所有权边界。
3. 部署的标准备份必须包含种子日志和引导收据，或者两者都不包含。
   不完整的对在创建和验证期间会被拒绝。
4. 恢复将活动部署、种子日志和引导接收字节与
   隔离前验证备份。仅数据库还原不会将较旧的快照与较新的引导生成相结合。
5. 对账锚定比较后再次读取最新的头部。出版物样本
   确定 `CURRENT` 或 `PROJECTION_LAGGING`。如果该样本不可用，则持久尝试是 `UNVERIFIABLE / HEAD_UNKNOWN` 以及实际的传输原因。

## 后果

- 部分引导数据库不会作为可恢复的标准备份发布。
- 如果快照后 bootstrap sidecar 发生更改，则在隔离之前恢复会失败。
- 锚定匹配在其检查点仍然有效，而发布新鲜度反映了稍后的情况
  头。当无法观察到最新的头部时，该报告绝不会发明滞后。
- 锁定仍为本地咨询 `flock`；没有引入分布式所有权主张。

## 验证

- 备份/恢复测试持有真实的引导锁，执行真实的better-sqlite3快照，拒绝
  不完整的和遗留的 sidecar 对，在隔离之前拒绝更改的活动 sidecar，并证明迁移安全备份在调用者持有的引导程序所有权下有效。
- 对账集成测试使用真实内存中的 SQLite 和
  受控链客户端。除了现有的首次读取失败案例之外，它们还涵盖了比较过程中头部前进和出版物头部读取失败的情况。
