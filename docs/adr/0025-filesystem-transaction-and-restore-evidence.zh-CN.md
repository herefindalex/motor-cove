# ADR 0025：文件系统、事务和恢复证据边界

[English](0025-filesystem-transaction-and-restore-evidence.md) · [繁體中文](0025-filesystem-transaction-and-restore-evidence.zh-TW.md)

- 状态：已接受
- 日期：2026-09-23

## 背景

三个恢复边界取决于早期检查后可能发生变化的证据。

Reset 在采取维护锁定之前验证了拥有的环境，然后使用数据库和报告目录进行破坏性清理。在所有权检查之后，进程可以用符号链接替换任一子进程。恢复验证了备份校验和，然后将源复制到暂存中，而无需证明暂存字节是经过验证的一代。交易恢复将显式丢失的随机数支持的原始哈希视为一般的 RPC 故障，因此该接口不会告诉操作员需要当前或替换的钱包哈希。

## 决定

重置会在采取维护门之后以及生成状态删除之前再次重新验证 `databaseDir` 和 `reportsDir`。每个路径必须存在，是目录，而不是符号链接，并且在真实环境根目录内解析。链回调和标记发布仅在锁定后检查之后发生。

恢复会像以前一样验证所选备份，将其数据库复制到操作拥有的暂存，并在隔离活动生成之前根据清单对暂存字节进行哈希处理。架构和部署检查仍然适用于同一暂存文件。

仅当日志具有随机数、没有记录的收据块并且检查的哈希是其保存的当前或原始哈希时，交易检查才会将显式未找到响应分类为 `REPLACEMENT_HASH_REQUIRED`。恢复会保留该分类并要求提供钱包活动哈希。候选人验证保持只读状态，并保留不可变的意图和原始哈希。

## 后果

- 所有权后符号链接替换无法重定向重置清理或到达链回调。
- 在验证和复制之间变化的备份源无法替代活动数据库。
- 当钱包更换或丢失已知的钱包时，操作员会收到精确的恢复操作
  随机数支持的交易。
- 通用 RPC 故障仍然无法获得观察证据，并不意味着需要更换。
- 这些决定都没有授权自动事务重新提交、环境重置或
  边车更换。

## 验证

- `DB-74` 用外部符号链接替换每个破坏性重置子项并证明零链调用，
  无标记，并保留外部字节。
- `DB-75` 在复制边界更改备份源并证明之前的校验和拒绝
  隔离，同时活动数据库保持可读。
- `TX-009` 涵盖了链检查、日志持久性以及经过验证的观察者提示
  当前或替换哈希，无需钱包写入。
