# ADR 0020：跨表交易觀察所有權

[English](0020-cross-tab-transaction-observation-ownership.md) · [简体中文](0020-cross-tab-transaction-observation-ownership.zh-CN.md)

- **狀態：**已接受
- **日期：** 2026-09-22

## 背景

每個 `TransactionObserver` 之前僅在其自己的 React 實例內防止重複工作。因此，兩個選項卡可以同時檢查相同的日誌操作。每次檢查在讀取 RPC 和 API 證據之前都會發布新的驗證產生。另一個選項卡可以在保存其結果之前取代該生成，因此兩個健康的觀察者可以重複返回 `SUPERSEDED` 而無需推進操作。

部署日誌已使用短 Web Lock，同時取代持久位元組。透過 RPC 和 HTTP 呼叫擴展寫鎖將序列化不相關的操作，並使儲存寫入依賴網路延遲。

## 決定

1. 事務觀察使用由部署 ID 和客戶端鍵入的專用排他鎖
   操作ID。鎖定包括重新載入最新的日誌版本、選擇驗證產生、讀取 RPC 或 API 證據以及嘗試受控日誌更新。
2. 自動輪詢使用 `ifAvailable` 請求 Web 鎖定。跳過繁忙的蜱蟲而不是
   等待和累積工作。明確手動候選檢查等待目前所有者，然後在建立其生成之前重新載入操作。
3. 不同的操作ID使用不同的觀察鎖並保持並發。現有的
   部署日誌寫鎖仍然只保護短的讀-修改-寫儲存部分。
4. 沒有 Web Locks 的瀏覽器使用模組級佇列。此後備僅協調觀察者
   相同的JavaScript領域；它不聲明交叉表所有權。關閉標籤會透過瀏覽器的鎖定生命週期釋放 Web 鎖定。

## 後果

- 當一項操作的健康觀察者無法在選項卡中不斷地相互取代時
  可以使用網路鎖。
- 手動證據檢查等待正在進行的自動檢查並使用最新的日誌
  修訂。自動輪詢保持有界且不建立隊列。
- 對一個操作的觀察不會阻止另一個操作或不相關的日誌寫入。
- 沒有 Web Locks 的瀏覽器中的跨裝置協調和跨選項卡協調仍然存在
  的保證。

## 驗證

- `browser-observation-coordinator.test.ts`檢查自動跳過、手動排隊、拒絕
  清理，以及一個JavaScript領域中的獨立操作鍵。
- `TransactionObserver.coordination.test.tsx`安裝並發觀察者，證明只有一個恢復
  產生開始，並驗證所有權重新載入最新的日誌修訂版。
- `journal-multitab.spec.ts`使用兩個真實的Chromium頁面來驗證Web Lock排除，獨立
  操作、不相關的日誌寫入以及所有者頁面關閉後的所有權轉移。
