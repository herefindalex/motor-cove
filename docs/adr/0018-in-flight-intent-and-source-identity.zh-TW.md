# ADR 0018：序列化正在進行的意圖並保留來源身份

[English](0018-in-flight-intent-and-source-identity.md) · [简体中文](0018-in-flight-intent-and-source-identity.zh-CN.md)

- **狀態：**已接受
- **日期：** 2026-09-22

## 背景

在錢包請求之前寫入不可變的交易意圖，但兩個 UI 呼叫可以在第一次模擬完成之前到達該邊界。持久日誌記錄了這兩次嘗試；它不決定哪個並發嘗試擁有打開錢包的權利。

NFT 所有權識別碼是元組 `(deployment, collection, token)`。 對帳先前將該身分簡化為 `token`，因此部署清單外部集合中的所有權行可以滿足預期行的要求或消失在預期行後面。

重新索引將遺失的來源行與儲存內容與其摘要或已完成區塊標頭相矛盾的來源證據區分開來。可以在正常倒帶期間插入缺失的行。必須先存檔並刪除現有的衝突內容，然後才能重新取得相同的事件標識。

## 決定

事務提交在第一個非同步步驟之前獲得完整的不可變意圖的同步、應用程式生命週期所有權。重複意圖失敗並顯示 `OPERATION_ALREADY_IN_FLIGHT`；不同的意圖保持獨立。頁面層級操作所有權也會在符合作業處於待處理狀態時停用它，並釋放 `finally` 中的所有權。持久的預錢包寫入和所有哈希/未知恢復規則仍然具有權威性。

對帳讀取 `collection_address` 的每個所有權行。只有清單集合才能滿足錨定的 `ownerOf` 結果。另一個集合的行是顯式 `UNEXPECTED_COLLECTION` 不匹配，包括當預期行也存在時。來自另一個部署的行保留在運行之外。

源刷新分類會在維護要求時進行評估，並在準備之前再次進行評估。解碼後的有效負載、原始信封、解碼器版本、記錄摘要或相同計數的完成區塊摘要不一致的非空源記錄需要經過驗證的刷新前備份和完整的掃描開始重新採集。純粹缺少的行會保留較窄的倒帶和插入路徑。正常攝取仍會拒絕衝突的事件身分；維護不會削弱該不變性。

## 後果

- 快速重複啟動一項操作會產生一個日誌意圖和一個錢包請求。
- 待處理狀態的範圍是根據銷售/操作確定的，而不是阻止不相關的市場工作。
- 對帳報告所有權差異中的集合身份，無法傳回 `MATCH`
  來自另一個集合的額外所有權行。
- 在活動來源行被刪除之前，衝突的來源證據在已驗證的備份中仍然可用。
  從鏈中重新取得。
- 當普通重新索引可以插入時，遺失的來源行不需要破壞性的來源刷新
  他們安全。

## 驗證邊界

單元和組件回歸使用受控待定模擬和真實的 React DOM。 SQLite/CLI 測試涵蓋所有權元組和來源分類。 Harness 擁有的 Anvil 測試涵蓋真實的對帳和經過驗證的來源存檔/重新獲取路徑。這些檢查不會建立手動錢包擴充行為或公共存檔-RPC 可用性。
