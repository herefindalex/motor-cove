# ADR 0017：可恢复的证据和无法获得的观察结果

[English](0017-recoverable-evidence-and-unavailable-observations.md) · [繁體中文](0017-recoverable-evidence-and-unavailable-observations.zh-TW.md)

- **状态：**已接受
- **日期：** 2026-09-22

## 背景

链种子可以在其第一次 `SUBMITTED` 日志写入完成之前接收交易哈希。浏览器还可以保留选项卡本地事务证据，同时策略暂时阻止对 `localStorage` 的访问。在这两种情况下，已知证据仍然存在，但存储故障不得被错误分类为未提交交易的证据。

对账具有相同的证据边界。一旦数据库和检查点可读，不可用的最新头 RPC 本身就是尝试检查的结果。仅保留较旧的存储报告会隐藏新的失败观察。

## 决定

链种子将提交失败与哈希后持久性失败分开。在短暂的首次写入失败后，它仅重试日志写入，将原始哈希保留为 `SUBMITTED`，并返回稳定的可恢复错误。稍后的调用将通过现有接收路径验证该哈希，并且不再调用提交回调。无哈希模糊性和更改的收据身份仍然无法关闭。

浏览器日志捕获适配器内的存储访问故障，记录 `STORAGE_UNAVAILABLE`，并将任何应用程序生命周期易失性条目合并到可读快照中。事务 UI 指出这些条目可能仅限选项卡，并且无法在重新加载后保存。预钱包持久意图失败仍然会阻止钱包请求。

对账包括报告生命周期中最新的头部采集。如果在检查点可用后该读取失败，它将保留 `UNVERIFIABLE` 和 `HEAD_UNKNOWN`，记录原因并以非零值退出。它不会重复使用较旧的头或较旧的报告作为当前运行的证据。

## 后果

- 一次性后哈希日志故障可以以只读方式恢复，无需重复的种子事务。
- 种子失败类别区分提交歧义、持久性恢复、搁浅
  准备，并更改收据证据。
- 选项卡本地事务哈希仍然可见，而持久浏览器存储则无法读取。
- 存储恢复并没有发明持久性；真正的重新加载仍然会丢失仅易失性的证据。
- 运营商和 API 消费者可以看到在头部获取之前对账尝试失败。
- 这些更改不会添加第二个日志、存储后端、对账表或恢复
  框架。
