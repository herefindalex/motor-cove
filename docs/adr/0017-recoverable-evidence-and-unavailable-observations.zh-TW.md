# ADR 0017：可恢復的證據和無法獲得的觀察結果

[English](0017-recoverable-evidence-and-unavailable-observations.md) · [简体中文](0017-recoverable-evidence-and-unavailable-observations.zh-CN.md)

- **狀態：**已接受
- **日期：** 2026-09-22

## 背景

鏈種子可以在其第一次 `SUBMITTED` 日誌寫入完成之前接收交易雜湊。瀏覽器還可以保留選項卡本地事務證據，同時策略暫時阻止對 `localStorage` 的存取。在這兩種情況下，已知證據仍然存在，但儲存故障不得被錯誤分類為未提交交易的證據。

對帳具有相同的證據邊界。一旦資料庫和檢查點可讀，不可用的最新頭 RPC 本身就是嘗試檢查的結果。僅保留較舊的儲存報告會隱藏新的失敗觀察。

## 決定

鏈種子將提交失敗與哈希後持久性失敗分開。在短暫的首次寫入失敗後，它僅重試日誌寫入，將原始雜湊保留為 `SUBMITTED`，並傳回穩定的可恢復錯誤。稍後的呼叫將透過現有接收路徑驗證該哈希，並且不再呼叫提交回調。無哈希模糊性和更改的收據身份仍然無法關閉。

瀏覽器日誌擷取適配器內的儲存存取故障，記錄 `STORAGE_UNAVAILABLE`，並將任何應用程式生命週期易失性條目合併到可讀快照中。交易 UI 指出這些條目可能僅限於選項卡，並且無法在重新載入後儲存。預錢包持久意圖失敗仍然會阻止錢包請求。

對帳包括報告生命週期中最新的頭部採集。如果在檢查點可用後該讀取失敗，它將保留 `UNVERIFIABLE` 和 `HEAD_UNKNOWN`，記錄原因並以非零值退出。它不會重複使用較舊的頭或較舊的報告作為當前運行的證據。

## 後果

- 一次性後哈希日誌故障可以以只讀方式恢復，無需重複的種子事務。
- 種子失敗類別區分提交歧義、持久性恢復、擱淺
  準備，並更改收據證據。
- 選項卡本機事務雜湊仍然可見，而持久瀏覽器儲存則無法讀取。
- 儲存恢復並沒有發明持久性；真正的重新載入仍然會遺失僅易失性的證據。
- 營運商和 API 消費者可以看到在頭部獲取之前對帳嘗試失敗。
- 這些變更不會添加第二個日誌、儲存後端、對帳表或恢復
  框架。
