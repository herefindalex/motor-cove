# ADR 0014：迁移延续和有界事务观察

[English](0014-migration-resume-and-observation-deadlines.md) · [繁體中文](0014-migration-resume-and-observation-deadlines.zh-TW.md)

- **状态：**已接受
- **日期：** 2026-09-22

## 背景

中断的迁移留下了两个有效状态之一：未更改的已知迁移前缀，或 `db_contract` 最终确定之前的当前 SQL 架构。持久 `MIGRATE` 标记无法识别目标迁移包，因此迁移命令拒绝每次重试，而通用恢复可以在不完成元数据的情况下清除当前架构标记。

浏览器事务恢复也有两个不对称的生存期规则。 HTTP 响应正文可以在标头到达后保持挂起状态，并无限期保留观察者单次飞行时隙。成功的收据仍处于自动本地观察状态，而恢复的收据则停止。

## 决定

1. 新的迁移标记记录了预期的模式契约和迁移包摘要。一个
   仅当操作、环境、数据库路径、模式契约和包摘要全部匹配时，迁移才可以继续现有标记。
2. 恢复在采取行动之前会验证本地历史。已知的旧前缀保持标记并返回
   `RERUN_MATCHING_MIGRATION`。当前模式经过验证，其 `db_contract` 元数据从检查的存储库合约中最终确定，再次验证为源数据库，然后才清除其标记。未知的历史记录、模式漂移和身份不匹配仍然无法解决。
3. Web HTTP 适配器为标头和正文消耗提供了一个 AbortController 截止时间。超时
   中止底层的fetch，通过恢复路径记录现有的不可用验证结果，并释放Observer单次槽。
4. `INCLUDED_SUCCESS`和`INCLUDED_REVERTED`使用相同的局部非最终自动观测
   政策。钱包被拒绝和提交前失败的情况仍然被排除在外。该策略支持重组和相同哈希重新包含检测；这不是公共网络的最终声明。

## 后果

- 操作员可以恢复确切的迁移包，而无需删除持久的故障证据。
- 当源合约元数据过时时，SQL 提交后的崩溃无法报告恢复。
- 停滞的响应主体具有有限的生命周期，并且不会永久抑制以后的只读
  验证尝试。
- 恢复的收据可以前进到孤立或重新包含的证据，而无需手动按下按钮。

- `tests/migrations/migrations.test.ts` 涵盖失败的前缀操作所需的恢复、捆绑包
  不匹配拒绝、匹配继续和当前模式元数据最终确定。
- `apps/web/src/integrations/http/motorcove-api.test.ts` 保持响应主体打开，观察中止，
  并完成以下请求。

  观察和提交前拒绝排除。
