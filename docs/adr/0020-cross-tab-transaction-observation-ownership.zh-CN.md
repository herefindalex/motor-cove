# ADR 0020：跨表交易观察所有权

[English](0020-cross-tab-transaction-observation-ownership.md) · [繁體中文](0020-cross-tab-transaction-observation-ownership.zh-TW.md)

- **状态：**已接受
- **日期：** 2026-09-22

## 背景

每个 `TransactionObserver` 之前仅在其自己的 React 实例内防止重复工作。因此，两个选项卡可以同时检查相同的日志操作。每次检查在读取 RPC 和 API 证据之前都会发布新的验证生成。另一个选项卡可以在保存其结果之前取代该生成，因此两个健康的观察者可以重复返回 `SUPERSEDED` 而无需推进操作。

部署日志已使用短 Web Lock，同时替换持久字节。通过 RPC 和 HTTP 调用扩展写锁将序列化不相关的操作，并使存储写入依赖于网络延迟。

## 决定

1. 事务观察使用由部署 ID 和客户端键入的专用排他锁
   操作ID。锁定包括重新加载最新的日志版本、选择验证生成、读取 RPC 或 API 证据以及尝试受控日志更新。
2. 自动轮询使用 `ifAvailable` 请求 Web 锁定。跳过繁忙的蜱虫而不是
   等待和积累工作。显式手动候选检查等待当前所有者，然后在创建其生成之前重新加载操作。
3. 不同的操作ID使用不同的观察锁并保持并发。现有的
   部署日志写锁仍然只保护短的读-修改-写存储部分。
4. 没有 Web Locks 的浏览器使用模块级队列。该后备仅协调观察者
   相同的JavaScript领域；它不声明交叉表所有权。关闭选项卡会通过浏览器的锁定生命周期释放 Web 锁。

## 后果

- 当一项操作的健康观察者无法在选项卡中不断地相互取代时
  可以使用网络锁。
- 手动证据检查等待正在进行的自动检查并使用最新的日志
  修订。自动轮询保持有界并且不建立队列。
- 对一个操作的观察不会阻止另一操作或不相关的日志写入。
- 没有 Web Locks 的浏览器中的跨设备协调和跨选项卡协调仍然存在
  的保证。

## 验证

- `browser-observation-coordinator.test.ts`检查自动跳过、手动排队、拒绝
  清理，以及一个JavaScript领域中的独立操作键。
- `TransactionObserver.coordination.test.tsx`安装并发观察者，证明只有一个恢复
  生成开始，并验证所有权重新加载最新的日志修订版。
- `journal-multitab.spec.ts`使用两个真实的Chromium页面来验证Web Lock排除，独立
  操作、不相关的日志写入以及所有者页面关闭后的所有权转移。
