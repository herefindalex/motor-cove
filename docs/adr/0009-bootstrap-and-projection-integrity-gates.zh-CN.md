# ADR 0009：引导程序和投影完整性门

[English](0009-bootstrap-and-projection-integrity-gates.md) · [繁體中文](0009-bootstrap-and-projection-integrity-gates.zh-TW.md)

## 状态

已接受。

## 背景

本地引导程序日志使顺序重试变得保守，但两个进程可以在保存其事务哈希之前读取相同的日志状态。即使数据库存储了不可变的部署描述符，API 启动也仅检查部署 ID。 对账仅在迭代预计销售额时检查付款索赔。 投影器还将缺少先决条件实体的拥有事件视为不相关事件。

这些差距可以发布混合部署，从诊断中省略不一致的投影行，或者在静默忽略事件后推进检查点。

## 决定

- 一个非阻塞咨询锁拥有托管环境的完整引导回调。它
  在迁移之前获取并通过链式接收和数据库引导持久化来保存。维护锁保留其现有的较窄生命周期，因此引导程序永远不会递归地采用相同的独占维护锁。
- 只读数据库读取器公开一个不可变的部署描述符。 API启动对比一下
  在服务器上构建或侦听之前使用已解析的清单。十六进制标识已大小写标准化；存储的清单哈希和语义清单内容均经过验证。
- 对账枚举链声明的每个规范 Sale ID 并独立枚举
  每个预计索赔行。额外的行仍然是仅报告不匹配。
- 当投影器拥有的事件缺少其先决条件 Sale 或
  Claim。 SQLite 工作单元回滚块、源事件、投影和检查点，然后在失败的事务之外记录 `RECOVERY_REQUIRED`。

## 后果

并发引导程序以 `RESOURCE_BUSY` 退出；操作员可以在所有者退出后重试，新进程将重新打开最新的日志。该锁位于一台主机本地，与支持的 SQLite 部署模型匹配。

当清单和数据库证据不一致时，API 启动失败关闭并释放其读取器。它不会修改任何一个源。

对账在锚定块上对每个规范 Sale 执行一次声明 getter 读取。这受到现有安全整数范围保护的限制，并且仍然是诊断操作。

投影完整性故障需要源或投影恢复。他们从不合成丢失的实体，也从不重新发送链上交易。
