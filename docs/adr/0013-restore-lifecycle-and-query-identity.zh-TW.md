# ADR 0013：復原檔案集、生命週期所有權與查詢身份

[English](0013-restore-lifecycle-and-query-identity.md) · [简体中文](0013-restore-lifecycle-and-query-identity.zh-CN.md)

- **狀態：**已接受
- **日期：** 2026-09-22

## 背景

三個邊界使用相關標識符，但沒有強制執行相同的生命週期。復原一次移動一個 SQLite 主檔案和 WAL/SHM sidecar，因此復原可以在前一個活動資料庫留下的 sidecar 旁邊安裝暫存快照。 Bootstrap 使用外部所有權鎖，而重設僅使用服務和寫入器閘。 Web 查詢金鑰包含部署 ID，但解析的 HTTP 回應仍可能攜帶來自另一個部署的出處。

## 決定

1. Restore復原將主檔案、WAL和SHM視為一代。在安裝分階段前
   獨立快照時，復原會將任何剩餘的活動 sidecar 移至該操作的隔離區。從隔離區回滾將其主檔案和 sidecar 重新組合起來。重複的活動和隔離的 sidecar 是不明確的，並且仍然需要恢復。
2. 重置在維護服務和寫入器鎖定之前取得相同的外部引導程式所有權。
   它必須在 `anvil_reset` 或檔案系統突變之前擁有兩者。固定順序是生命週期所有權、服務門、然後編寫者門。
3. Web 快照請求在其查詢功能中擷取預期的部署。 HTTP 轉接器
   解析電匯合約，然後將響應來源與預期部署進行比較。不匹配的資料會被拒絕，而不是被快取或重新標記。然後配置輪詢可以提供替換部署上下文；輪詢不被視為身份驗證。

## 後果

- 分階段備份無法重播它所取代的資料庫所留下的熱 WAL。
- 重置不能與引導交易或其持久性鏈種子日誌競爭。
- 查詢鍵仍然是快取命名空間；回應來源是獨立的運行時檢查。
- SQLite 碰撞測試使用線束擁有的臨時資料庫和被殺死的子寫入器。他們不
  聲稱硬體斷電行為。

## 驗證

- `tests/recovery/backup-restore.test.ts` 在子進程中創建一個已提交的熱 WAL，並殺死它
  過程，重現僅主文件開關，並驗證恢復返回備份值。
- `tests/database/reset-cli.test.ts`持有真正的自舉程式`flock`，證明`anvil_reset`不是
  調用，釋放所有權，並證明重置可以完成。
- `apps/web/src/integrations/http/motorcove-api.test.ts` 检查 Sale、车辆和系统快照
  拒绝不同的部署，不要填充错误的 TanStack Query 缓存条目，在替换部署密钥下恢复，并接受等效的十六进制大小写。
