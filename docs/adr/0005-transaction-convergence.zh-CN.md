# ADR 0005：只读事务恢复和快照收敛

[English](0005-transaction-convergence.md) · [繁體中文](0005-transaction-convergence.zh-TW.md)

- **状态：**已接受
- **范围：** `SALE-002`、浏览器日志恢复、资金观察、Indexer提交故障

## 背景

钱包哈希、成功收据、索引事件和预计的 Sale 在不同时间变得可见。任何间隙期间的重新加载都必须通过读取证据来恢复，而无需重复付款。仅比较检查点高度或组合来自不同 SQLite 时刻的行也可能产生错误的完成结果。

## 决定

在调用钱包之前保留不可变的资金意图和钱包请求边界。将提交保留在专用的申请功能中。 Recovery只有链读、API读和日志端口；架构检查拒绝钱包写入依赖性。

使用全有或全无事件选择器扩展现有销售 GET 路由。数据库读取器从一次读取事务中返回覆盖范围、请求高度规范标头、事件查找、投影效果、新鲜度和出处。一致的资金效应接受 `FUNDED`、`COMPLETED` 或 `EXPIRED`，并且不需要付款索赔。

保留现有的Indexer交易边界。仅测试同步故障钩子为子进程 `SIGKILL` 测试提供精确的 pre-BEGIN、pre-COMMIT 和 post-COMMIT 进程障碍。

为每个异步验证分配一个生成 ID，并仅在该生成保持当前状态时将其结果合并到最新保存的日志条目中。随机数丰富还会重新加载最新条目并仅更改随机数。使用一个选择器定义当前的投影成功，该选择器需要包含成功、成功收据和反映的投影。

## 后果

- 重新加载、轮询、候选哈希验证和投影重试无法提交交易。
- 丢失的哈希仍然可操作 `UNKNOWN`；用户界面从未将其他付款描述为安全的。
- 成功的链执行和投影收敛仍然是独立的用户可见事实。
- 相同随机数替换被分类为重新定价、取消或任何之前的不同调用
  更换收据即可满足原意。
- 孤立的收据证据仍然可见，为 `NONCANONICAL`；相同哈希重新包含必须建立
  新的规范收据和事件标识。
- 缓慢的验证或随机数查找无法取代较新的收据或投影证据。
- 选择器请求不能改变 Indexer 运行状况或数据库状态。
- WAL 进程终止证据与正常回滚和硬件断电分开记录。
