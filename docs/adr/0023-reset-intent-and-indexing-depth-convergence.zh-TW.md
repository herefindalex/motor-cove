# ADR 0023：重置意圖和索引深度收斂

[English](0023-reset-intent-and-indexing-depth-convergence.md) · [简体中文](0023-reset-intent-and-indexing-depth-convergence.zh-CN.md)

- **狀態：**已接受
- **日期：** 2026-09-22

## 背景

在發布其持久維護標記之前，本地重置命令會呼叫 `anvil_reset`。在該時間間隔內的進程死亡導致舊資料庫和部署 sidecar 旁的新鏈產生沒有復原證據。如果標記出現後本地刪除失敗，通用資料庫復原也可以在單獨驗證舊資料庫後清除重置標記。

Indexer 資格為 `head - indexingDepth`。因此，在操作員增加深度後，深度為零索引的資料庫可能在合格目標上方有一個檢查點。正常空閒路徑之前標記為投影 `CURRENT`，而沒有收回新保留的區塊。

## 決定

1. Reset 在呼叫鏈重置回呼之前發布 `RESET / PREPARED`。回調後
   成功，它發布 `CHAIN_RESET`，清除生成的本地狀態，發布 `LOCAL_STATE_CLEARED`，然後才清除標記。
2. 失敗的標記保留 `resetPhase`。復原永遠不會將有效的舊資料庫視為重置
   完成證據。 `PREPARED` 需要執行操作，因為連鎖結果未知； `CHAIN_RESET`可以在引導和維護所有權下完成冪等本地清理。
3. 如果持久檢查點超出目前符合條件的索引目標，則正常攝取標記
   需要恢復並停止。操作員使用現有的明確重新索引工作流程來收斂到更嚴格的目標。運轉時不會靜默倒回投影。
4. 降低索引深度仍然是普通的向前追趕。符合條件的深度不變
   檢查點仍然是一個閒置的健康輪詢。

## 後果

- 連鎖副作用後的進程死亡總是會留下一個重置標記以供診斷。
- 重置恢復是特定於階段的，不能透過模式驗證來祝福老一輩。
- 增加最終性保留將失敗關閉，直到明確重新索引完成為止。
- 深度規則不會新增第二個索引器或維護機制。

## 驗證

- 真實的子程序記錄受控的鏈生成副作用，在重置期間暫停
  回調，接收 `SIGKILL`，並留下 `PREPARED` 加上舊的本地代。恢復報告所需的操作。
- 真正的諮詢鎖定和檔案系統測試涵蓋 RPC 排序之前的標記、之後的清理失敗
  `CHAIN_RESET`，冪等恢復，保留備份和鎖定 inode，以及託管 Anvil 重置路徑。
- 應用測試涵蓋增加深度、減少深度、不合格塊和不變深度
  空閒健康。
