# ADR 0018：序列化正在进行的意图并保留源身份

[English](0018-in-flight-intent-and-source-identity.md) · [繁體中文](0018-in-flight-intent-and-source-identity.zh-TW.md)

- **状态：**已接受
- **日期：** 2026-09-22

## 背景

在钱包请求之前写入不可变的交易意图，但两个 UI 调用可以在第一次模拟完成之前到达该边界。持久日志记录了这两次尝试；它不决定哪个并发尝试拥有打开钱包的权利。

NFT 所有权标识是元组 `(deployment, collection, token)`。 对账之前将该身份简化为 `token`，因此部署清单外部集合中的所有权行可以满足预期行的要求或消失在预期行后面。

重新索引将丢失的源行与存储内容与其摘要或已完成块标头相矛盾的源证据区分开来。可以在正常倒带期间插入缺失的行。必须先存档并删除现有的冲突内容，然后才能重新获取相同的事件标识。

## 决定

事务提交在第一个异步步骤之前获得完整的不可变意图的同步、应用程序生命周期所有权。重复意图失败并显示 `OPERATION_ALREADY_IN_FLIGHT`；不同的意图保持独立。页面级操作所有权还会在匹配操作处于待处理状态时禁用它，并释放 `finally` 中的所有权。持久的预钱包写入和所有哈希/未知恢复规则仍然具有权威性。

对账读取 `collection_address` 的每个所有权行。只有清单集合才能满足锚定的 `ownerOf` 结果。另一个集合的行是显式 `UNEXPECTED_COLLECTION` 不匹配，包括当预期行也存在时。来自另一个部署的行保留在运行之外。

源刷新分类会在维护要求时进行评估，并在准备之前再次进行评估。解码后的有效负载、原始信封、解码器版本、记录摘要或相同计数的完成块摘要不一致的非空源记录需要经过验证的刷新前备份和完整的扫描开始重新采集。纯粹缺失的行会保留较窄的倒带和插入路径。正常摄取仍然会拒绝冲突的事件身份；维护不会削弱该不变性。

## 后果

- 快速重复激活一项操作会产生一个日志意图和一个钱包请求。
- 待处理状态的范围是根据销售/操作确定的，而不是阻止不相关的市场工作。
- 对账报告所有权差异中的集合身份，无法返回 `MATCH`
  来自另一个集合的额外所有权行。
- 在活动源行被删除之前，冲突的源证据在已验证的备份中仍然可用。
  从链中重新获取。
- 当普通重新索引可以插入时，丢失的源行不需要破坏性的源刷新
  他们安全。

## 验证边界

单元和组件回归使用受控待定模拟和真实的 React DOM。 SQLite/CLI 测试涵盖所有权元组和源分类。 Harness 拥有的 Anvil 测试涵盖真实的对账和经过验证的源存档/重新获取路径。这些检查不会建立手动钱包扩展行为或公共存档-RPC 可用性。
