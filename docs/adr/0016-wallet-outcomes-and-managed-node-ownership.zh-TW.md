# ADR 0016：錢包結果和託管本地節點所有權

[English](0016-wallet-outcomes-and-managed-node-ownership.md) · [简体中文](0016-wallet-outcomes-and-managed-node-ownership.zh-CN.md)

- **狀態：**已接受
- **日期：** 2026-09-22

## 背景

錢包請求和交易觀察是並發的證據來源。當錢包請求仍然打開時，恢復觀察者可以推進無哈希日誌條目。將錢包拒絕視為替換交易狀態會在修訂衝突中遺失拒絕或刪除同時發現的交易雜湊。

本地重置的影響範圍比資料庫環境更廣。 `anvil_reset` 變更整個 RPC 節點，因此環境範圍的資料庫鎖定無法保護指向相同節點的第二個託管環境。

## 決定

日誌記錄錢包請求結果與交易狀態分開。只有當不可變意圖和錢包請求開始時間仍然匹配時，拒絕或未知錢包回應才會合併到最新版本。交易證據取決於交易狀態和哈希值。儲存故障僅在應用程式生命週期易失性覆蓋中保留結果，且 UI 會識別重新載入限制。

每個託管環境在 `managed-node.json` 中宣告一個標準化環回 HTTP 端點。聲明和所有權檢查使用工作區範圍的 `managed-nodes.lock`。 Bootstrap 在鏈寫入之前宣告節點。 Indexer啟動和重置驗證所有權。重置會保留綁定，以便可以在同一專用節點上重建相同的環境。

## 後果

- 錢包拒絕在觀察者修訂競賽中倖存下來，而不會刪除並發的哈希證據。
- 耐用和僅限應用程式生命週期的錢包結果仍然是有區別的。
- 兩個託管環境不能宣告同一環回端點和連接埠的別名。
- 遺失、衝突、損壞或變更的節點綁定在索引器啟動之前關閉失敗或
  `anvil_reset`.
- 此所有權模型不識別不相關的進程、連接埠轉送或不同的連接埠
  達到相同的外部服務。受管理的本機環境需要專用的線束擁有的環回節點。
