# ADR 0015：投影恢复转换和部署前证据

[English](0015-projection-transition-and-predeployment-evidence.md) · [繁體中文](0015-projection-transition-and-predeployment-evidence.zh-TW.md)

- **状态：**已接受
- **日期：** 2026-09-22

## 背景

重建正确地拒绝了不完整的本地源日志，但其持久的 `REBUILD_PROJECTION` 标记随后阻止了记录的重新索引恢复命令获取操作。浏览器恢复核心接受替代交易哈希，而 UI 仅在哈希不存在时才公开该输入。迁移备份还需要为每个较旧的初始化模式提供一个部署 sidecar，包括从未注册过链部署的有效数据库。

## 决定

1. 投影维护允许一种显式操作转换：失败的重建，其保存的
   仅当调用者选择加入、部署/环境/数据库/架构身份匹配，并且重新索引从所需的部署扫描开始块（带有捕获的目标块和哈希）开始时，以 `REBUILD_SOURCE_INCOMPLETE` 开头的错误可能会成为重新索引。当独占门保持保留时，转换就会发生。新标记接收新操作 ID 并记录旧操作 ID、类型和错误。
2. 当保存的交易哈希存在但验证不可用时，恢复 UI 会显示
   可选的替代哈希。现有的只读验证器仍然检查保存的链、部署、帐户、目标、调用数据、值和特定于操作的证据。它保留原始哈希值并且不会获得钱包写入端口。
3. 备份清单将其源明确分类为 `DEPLOYED` 或 `PREDEPLOYMENT`。一个
   仅当数据库具有零部署行且部署、引导接收和种子日志 sidecar 均不存在时，预部署快照才有效。已部署的源仍然需要匹配的部署 sidecar。部署前备份保留迁移数据，但不被部署绑定的恢复命令接受。

## 后果

- 操作员可以使用记录的完整重新索引来跟踪重建源失败，而无需删除
  标记或在维护所有权方面打开差距。
- 候选哈希可以恢复替换或丢失的提供者观察，同时保留
  原始交易历史和不确定性。
- 架构迁移可以保护初始化的预部署数据库，而无需创建链
  身份。 Sidecar 分歧仍然未能解决。
- 现有时间线范围的 Playwright 定位器仍然是重复哈希表示的证明；
  警报和时间线可能都显示相同的哈希值。

## 验证

- `tests/database/projection-maintenance.test.ts` 验证未经授权和错误启动转换
  失败，而显式完整重新索引记录沿袭并成功。
- `apps/web/src/integrations/evm/TransactionObserver.test.tsx` 验证现有的不可用哈希
  可以提交只读恢复的替代方案。
- `tests/migrations/migrations.test.ts` 执行真正的 `0000` 到 `0001` 部署前备份并
  升级、检查清单分类、保留目录数据并保留零部署行。
- `tests/e2e/marketplace.spec.ts` 将非持久哈希断言范围限定为指定事务
  时间线，同时通知还显示哈希值。
