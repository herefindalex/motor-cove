# ADR 0027：恢复障碍和引导程序证据发布

[English](0027-recovery-barrier-and-bootstrap-publication.md) · [繁體中文](0027-recovery-barrier-and-bootstrap-publication.zh-TW.md)

- 状态：已接受
- 日期：2026-09-23

## 背景

`RECOVERY_REQUIRED`记录证实了投影完整性的证据。临时传输失败、普通提交或运行时重新启动不得删除它。维护标记单独拥有正在进行的重建或重新索引。引导接收和部署 sidecar 还需要完整的、身份绑定的内容：文件存在和匹配的校验和本身并不能确定完成。最后，重播本地日志不观察直播链，并且一定不会更新RPC的新鲜度。

## 决定

正常的投影写入器拒绝启动，而 `RECOVERY_REQUIRED` 则保留。普通的陈旧和当前转换会保留该状态，而普通的提交会在更改源、投影或检查点行之前拒绝。维护编排在发布标记之前会读取其独占门下的持久原因。规范或来源可疑允许重新索引；仅投影器完整性原因允许在本地源验证后重建。不支持的重建请求会使现有标记和投影保持不变。

对账在其自己的维护门下仍可作为诊断报告使用。它可以读取投影并保存`UNVERIFIABLE`报告，而无需打开普通投影写入器或清除恢复证据。

Reindex通过倒回、本地重放和追赶来保存恢复原因。在这个原因仍然存在的情况下，其维护拥有的商店可能会承诺。只有达到规范目标才能释放 `SYNCING` 的障碍；下一个实时观察确定是否是 `CURRENT`。失败的维护回调会恢复之前的屏障并留下失败的标记。仅投影器的重建可以在源验证和成功的本地事务后发布其重建的投影。

Bootstrap 收据内容根据格式版本、环境、部署、目标、构建 ID 和时间戳进行解析。收据和部署清单发布会写入一个唯一的临时文件，刷新它，将其重命名到位，然后同步父目录。验证预先存在的最终文件；冲突或格式错误的内容将被拒绝。即使后来的合法投影重建更改了当前构建 ID，现有的引导收据仍保留历史证据。当后续交易推进链头时，其目标块和哈希值也仍然是原始完成锚。标准部署的备份需要配对的种子日志和有效的收据。备份验证会再次检查复制的收据，即使其记录的校验和匹配也是如此。

本地 `rebuildFromJournal()` 不再推进 `worker_heartbeat_at`。成功的局部投影重建和新的 RPC 观测是不同的主张；在工作人员对链进行投票之前，读者可能仍然会呈现陈旧的观察新鲜度。

## 验证

R25 回归测试涵盖屏障持久性、维护资格和后置条件、重新索引重播、收据发布和备份验证以及本地重建新鲜度。验证记录区分重点测试、完整本地网关和浏览器证据。
