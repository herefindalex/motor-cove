# ADR 0016：钱包结果和托管本地节点所有权

[English](0016-wallet-outcomes-and-managed-node-ownership.md) · [繁體中文](0016-wallet-outcomes-and-managed-node-ownership.zh-TW.md)

- **状态：**已接受
- **日期：** 2026-09-22

## 背景

钱包请求和交易观察是并发的证据来源。当钱包请求仍然打开时，恢复观察者可以推进无哈希日志条目。将钱包拒绝视为替换交易状态会在修订冲突中丢失拒绝或删除同时发现的交易哈希。

本地重置的影响范围比数据库环境更广。 `anvil_reset` 更改整个 RPC 节点，因此环境范围的数据库锁无法保护指向同一节点的第二个托管环境。

## 决定

日志记录钱包请求结果与交易状态分开。仅当不可变意图和钱包请求开始时间仍然匹配时，拒绝或未知钱包响应才会合并到最新版本中。交易证据取决于交易状态和哈希值。存储故障仅在应用程序生命周期易失性覆盖中保留结果，并且 UI 会识别重新加载限制。

每个托管环境在 `managed-node.json` 中声明一个标准化环回 HTTP 端点。声明和所有权检查使用工作区范围的 `managed-nodes.lock`。 Bootstrap 在链写入之前声明节点。 Indexer启动和重置验证所有权。重置会保留绑定，以便可以在同一专用节点上重建相同的环境。

## 后果

- 钱包拒绝在观察者修订竞赛中幸存下来，而不会删除并发的哈希证据。
- 耐用和仅限应用程序生命周期的钱包结果仍然是有区别的。
- 两个托管环境不能声明同一环回端点和端口的别名。
- 丢失、冲突、损坏或更改的节点绑定在索引器启动之前关闭失败或
  `anvil_reset`.
- 此所有权模型不识别不相关的进程、端口转发或不同的端口
  达到相同的外部服务。受管理的本地环境需要专用的线束拥有的环回节点。
