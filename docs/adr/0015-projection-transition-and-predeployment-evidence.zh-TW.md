# ADR 0015：投影復原轉換與部署前證據

[English](0015-projection-transition-and-predeployment-evidence.md) · [简体中文](0015-projection-transition-and-predeployment-evidence.zh-CN.md)

- **狀態：**已接受
- **日期：** 2026-09-22

## 背景

重建正確地拒絕了不完整的本地來源日誌，但其持久的 `REBUILD_PROJECTION` 標記隨後阻止了記錄的重新索引恢復命令獲取操作。瀏覽器恢復核心接受替代交易哈希，而 UI 僅在哈希不存在時才公開該輸入。遷移備份還需要為每個較舊的初始化模式提供一個部署 sidecar，包括從未註冊過鏈部署的有效資料庫。

## 決定

1. 投影維護允許一種明確操作轉換：失敗的重建，其保存的
   只有當呼叫者選擇加入、部署/環境/資料庫/架構身份匹配，並且重新索引從所需的部署掃描開始區塊（帶有捕獲的目標區塊和雜湊）開始時，以 `REBUILD_SOURCE_INCOMPLETE` 開頭的錯誤可能會成為重新索引。當獨佔門保持保留時，轉換就會發生。新標記接收新操作 ID 並記錄舊操作 ID、類型和錯誤。
2. 當已儲存的交易哈希存在但驗證不可用時，恢復 UI 會顯示
   可選的替代哈希。現有的唯讀驗證器仍然檢查已儲存的鏈、部署、帳戶、目標、呼叫資料、值和特定於操作的證據。它保留原始哈希值並且不會獲得錢包寫入連接埠。
3. 備份清單將其來源明確分類為 `DEPLOYED` 或 `PREDEPLOYMENT`。一個
   只有當資料庫具有零部署行且部署、引導接收和種子日誌 sidecar 均不存在時，預先部署快照才有效。已部署的來源仍然需要匹配的部署 sidecar。部署前備份保留遷移數據，但不被部署綁定的恢復命令接受。

## 後果

- 操作員可以使用記錄的完整重新索引來追蹤重建來源失敗，而無需刪除
  標記或在維護所有權方面打開差距。
- 候選哈希可以恢復替換或遺失的提供者觀察，同時保留
  原始交易歷史和不確定性。
- 架構遷移可以保護初始化的預先部署資料庫，而無需建立鏈
  身份。 Sidecar 分歧仍然未能解決。
- 現有時間軸範圍的 Playwright 定位器仍然是重複哈希表示的證明；
  警報和時間軸可能都顯示相同的雜湊值。

## 驗證

- `tests/database/projection-maintenance.test.ts` 驗證未經授權和錯誤啟動轉換
  失敗，而顯式完整重新索引記錄沿襲並成功。
- `apps/web/src/integrations/evm/TransactionObserver.test.tsx` 驗證現有的不可用哈希
  可以提交只讀恢復的替代方案。
- `tests/migrations/migrations.test.ts` 執行真正的 `0000` 到 `0001` 部署前備份並
  升級、檢查清單分類、保留目錄資料並保留零部署行。
- `tests/e2e/marketplace.spec.ts` 將非持久雜湊斷言範圍限定為指定事務
  時間軸，同時通知也顯示雜湊值。
