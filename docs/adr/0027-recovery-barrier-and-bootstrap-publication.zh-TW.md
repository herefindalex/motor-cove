# ADR 0027：恢復障礙和引導程式證據發布

[English](0027-recovery-barrier-and-bootstrap-publication.md) · [简体中文](0027-recovery-barrier-and-bootstrap-publication.zh-CN.md)

- 狀態：已接受
- 日期：2026-09-23

## 背景

`RECOVERY_REQUIRED`记录证实了投影完整性的证据。臨時傳輸失敗、普通提交或運行時重新啟動不得刪除它。維護標記單獨擁有正在進行的重建或重新索引。引導接收和部署 sidecar 還需要完整的、身分綁定的內容：檔案存在和匹配的校驗和本身並不能確定完成。最后，重播本地日誌不观察直播链，并且一定不会更新RPC的新鲜度。

## 決定

正常的投影写入器拒绝启动，而 `RECOVERY_REQUIRED` 则保留。普通的陈旧和当前转换会保留该状态，而普通的提交会在更改源、投影或检查点行之前拒绝。維護編排在發布標記之前會讀取其獨佔門下的持久原因。规范或来源可疑允许重新索引；仅投影器完整性原因允许在本地源验证后重建。不支持的重建请求会使现有标记和投影保持不变。

對帳在其自己的维护门下仍可作为诊断报告使用。它可以读取投影并保存`UNVERIFIABLE`报告，而无需打开普通投影写入器或清除恢复证据。

Reindex透過倒回、本地重播和追趕來保存恢復原因。在這個原因仍然存在的情況下，其維護擁有的商店可能會承諾。只有達到規範目標才能釋放 `SYNCING` 的障礙；下一個即時觀察確定是否為 `CURRENT`。失敗的維護回調會恢復先前的屏障並留下失敗的標記。仅投影器的重建可以在源验证和成功的本地事务后发布其重建的投影。

Bootstrap 收據內容根據格式版本、環境、部署、目標、建置 ID 和時間戳進行解析。收據和部署清單發布會寫入一個唯一的臨時文件，刷新它，將其重命名到位，然後同步父目錄。驗證預先存在的最終文件；衝突或格式錯誤的內容將被拒絕。即使後來的合法投影重建更改了當前建置 ID，現有的引導收據仍保留歷史證據。當後續交易推進鏈頭時，其目標區塊和雜湊值也仍然是原始完成錨。標準部署的備份需要配對的種子日誌和有效的收據。備份驗證會再次檢查複製的收據，即使其記錄的校驗和匹配也是如此。

本地 `rebuildFromJournal()` 不再推進 `worker_heartbeat_at`。成功的局部投影重建和新的 RPC 觀測是不同的主張；在工作人員對鏈進行投票之前，讀者可能仍然會呈現陳舊的觀察新鮮度。

## 驗證

R25 回歸測試涵蓋屏障持久性、維護資格和後置條件、重新索引重播、收據發布和備份驗證以及本地重建新鮮度。驗證記錄區分重點測試、完整本機網關和瀏覽器證據。
