# ADR 0023：重置意图和索引深度收敛

[English](0023-reset-intent-and-indexing-depth-convergence.md) · [繁體中文](0023-reset-intent-and-indexing-depth-convergence.zh-TW.md)

- **状态：**已接受
- **日期：** 2026-09-22

## 背景

在发布其持久维护标记之前，本地重置命令调用 `anvil_reset`。该时间间隔内的进程死亡导致旧数据库和部署 sidecar 旁边的新链生成没有恢复证据。如果标记出现后本地删除失败，通用数据库恢复也可以在单独验证旧数据库后清除重置标记。

Indexer 资格为 `head - indexingDepth`。因此，在操作员增加深度后，深度为零索引的数据库可能在合格目标上方有一个检查点。正常空闲路径之前标记为投影 `CURRENT`，而没有收回新保留的块。

## 决定

1. Reset 在调用链重置回调之前发布 `RESET / PREPARED`。回调后
   成功，它发布 `CHAIN_RESET`，清除生成的本地状态，发布 `LOCAL_STATE_CLEARED`，然后才清除标记。
2. 失败的标记保留 `resetPhase`。恢复永远不会将有效的旧数据库视为重置
   完成证据。 `PREPARED` 需要执行操作，因为连锁结果未知； `CHAIN_RESET`可以在引导和维护所有权下完成幂等本地清理。
3. 如果持久检查点超出当前符合条件的索引目标，则正常摄取标记
   需要恢复并停止。操作员使用现有的显式重新索引工作流程来收敛到更严格的目标。运行时不会静默倒回投影。
4. 降低索引深度仍然是普通的向前追赶。符合条件的深度不变
   检查点仍然是一个闲置的健康轮询。

## 后果

- 连锁副作用后的进程死亡总是会留下一个重置标记以供诊断。
- 重置恢复是特定于阶段的，不能通过模式验证来祝福老一代。
- 增加最终性保留将失败关闭，直到显式重新索引完成为止。
- 深度规则不会添加第二个索引器或维护机制。

## 验证

- 真实的子进程记录受控的链生成副作用，在重置期间暂停
  回调，接收 `SIGKILL`，并留下 `PREPARED` 加上旧的本地代。恢复报告所需的操作。
- 真正的咨询锁和文件系统测试涵盖 RPC 排序之前的标记、之后的清理失败
  `CHAIN_RESET`，幂等恢复，保留备份和锁定 inode，以及托管 Anvil 重置路径。
- 应用测试涵盖增加深度、减少深度、无合格块和不变深度
  空闲健康。
