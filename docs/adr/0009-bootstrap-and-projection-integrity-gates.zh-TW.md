# ADR 0009：引導程式和投影完整性門

[English](0009-bootstrap-and-projection-integrity-gates.md) · [简体中文](0009-bootstrap-and-projection-integrity-gates.zh-CN.md)

## 狀態

已接受。

## 背景

本機引導程式日誌使順序重試變得保守，但兩個進程可以在保存其事務哈希之前讀取相同的日誌狀態。即使資料庫儲存了不可變的部署描述符，API 啟動也僅檢查部署 ID。 對帳僅在迭代預計銷售額時檢查付款索賠。 投影器也將缺少先決條件實體的擁有事件視為不相關事件。

這些差距可以發布混合部署，從診斷中省略不一致的投影行，或在靜默忽略事件後推進檢查點。

## 決定

- 一個非阻塞諮詢鎖定擁有託管環境的完整引導回調。它
  在遷移之前獲取並透過鍊式接收和資料庫引導持久化來保存。維護鎖保留其現有的較窄生命週期，因此引導程式永遠不會遞歸地採用相同的獨佔維護鎖。
- 只讀資料庫讀取器公開一個不可變的部署描述符。 API启动对比一下
  在伺服器上建置或偵聽之前使用已解析的清單。十六進位標識已大小寫標準化；儲存的清單雜湊和語意清單內容均經過驗證。
- 對帳枚舉鏈聲明的每個規範 Sale ID 並獨立枚舉
  每個預計索賠行。額外的行仍然是僅報告不匹配。
- 當投影器擁有的事件缺少其先決條件 Sale 或
  Claim。 SQLite 工作單元回滾區塊、來源事件、投影和檢查點，然後在失敗的事務之外記錄 `RECOVERY_REQUIRED`。

## 後果

並發引導程式以 `RESOURCE_BUSY` 退出；操作員可以在所有者退出後重試，新進程將重新開啟最新的日誌。該鎖位於一台主機本地，與支援的 SQLite 部署模型相符。

當清單和資料庫證據不一致時，API 啟動失敗關閉並釋放其讀取器。它不會修改任何一個來源。

對帳在錨定區塊上對每個規範 Sale 執行一次宣告 getter 讀取。這受到現有安全整數範圍保護的限制，並且仍然是診斷操作。

投影完整性故障需要來源或投影復原。他們從不合成失去的實體，也從不重新發送鏈上交易。
