# ADR 0011：重新检查实时身份并保留诊断证据

[English](0011-runtime-identity-and-diagnostic-evidence.md) · [繁體中文](0011-runtime-identity-and-diagnostic-evidence.zh-TW.md)

## 状态

已接受。

## 背景

几个现有的安全边界单独来看是正确的，但没有涵盖完整的运行时生命周期。交易意图捕获了部署身份，但其最终的钱包前检查仅比较了帐户和链。目录播种获得了维护锁定，但没有拒绝较早失败的维护标记。发出信号的 `flock` 帮助程序可能会在清理安装其退出侦听器之前退出。通过普通锚点的客户端导航破坏了当返回的事务哈希无法持久时使用的内存回退。

诊断事件源还保留了移位的源事件，而没有说明哪些行当前是规范的，并且体系结构检查器仅通过其包说明符识别 Web 到数据库违规。这些差距不需要新的事务日志、锁服务、事件存储或依赖分析器。

## 决定

- 最终的钱包前上下文检查会比较账户、链、部署 ID、协议版本、NFT
  地址和托管地址。模拟挂起时的配置更改会使钱包调用之前的旧请求无效。历史意图保留其原始部署标识。
- 内部市场导航使用 React Router 链接。选项卡本地易失性事务
  因此，覆盖层可以在运行的应用程序中的路由更改中幸存下来。真正的重新加载或选项卡关闭仍然会丢失非持久的证据，并且仍然存在明确的恢复限制。
- 目录播种获得现有的独占门，然后拒绝任何不完整的维护
  在打开数据库或更改目录行之前进行标记。只有匹配的恢复命令才能解析该标记。
- 当子进程生成时，咨询锁助手捕获一个完成承诺。正常退出，
  信号退出、子错误、重复释放和复合清理都观察到相同的结果。
- 原始的近期事件提要保留了规范的和替换的审计历史记录。每场活动都承载着
  `canonical`、`scanComplete`、以及区块的`sourceLogScopeHash`；消费者必须评估每行的这些字段，而不是从响应级别检查点推断有效性。
- 架构规则评估已解析目标的包所有权以及书面导入
  说明符。相对路径、别名和重新导出不能绕过 Web 到数据库边界。
- 有状态托管套件独立地对销售资金和可索赔的付款索赔进行总和。它断言
  该预期未偿金额等于 `totalLiability`，并且该合约余额涵盖该独立计算的金额。成功的转换计数器与操作尝试保持分离。

## 后果

模拟期间的部署替换不会因过时操作产生钱包请求。已经开始的成功钱包请求仍然遵循现有的哈希和`UNKNOWN`恢复规则； UI 并不声称它从未提交过。

即使在操作系统锁被释放之后，不完整的维护标记也可以防止目录突变。只读诊断和身份匹配恢复仍然可用。

事件 API 是审核源，而不是仅限规范的业务源。流离失所的事件仍然是可检查的，并且可以在不删除其源证据的情况下再次成为规范。每个事件的源范围与响应包络的当前投影范围不同。

额外的契约不变量强化了有关记录会计的证据。它仍然是本地 Foundry 证据，并不构成外部审计或公共网络安全声明。
