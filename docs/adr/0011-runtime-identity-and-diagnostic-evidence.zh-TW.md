# ADR 0011：重新檢查即時身分並保留診斷證據

[English](0011-runtime-identity-and-diagnostic-evidence.md) · [简体中文](0011-runtime-identity-and-diagnostic-evidence.zh-CN.md)

## 狀態

已接受。

## 背景

幾個現有的安全邊界單獨來看是正確的，但沒有涵蓋完整的運行時生命週期。交易意圖捕獲了部署身份，但其最終的錢包前檢查僅比較了帳戶和鏈。目錄播種獲得了維護鎖定，但沒有拒絕較早失敗的維護標記。發出訊號的 `flock` 幫助程式可能會在清理安裝其退出偵聽器之前退出。透過普通錨點的客戶端導航破壞了當傳回的交易哈希無法持久時使用的記憶體回退。

診斷事件來源也保留了移位的來源事件，而沒有說明哪些行目前是規範的，並且體系結構檢查器僅透過其套件說明符識別 Web 到資料庫違規。這些差距不需要新的交易日誌、鎖定服務、事件儲存或依賴分析器。

## 決定

- 最終的錢包前上下文檢查會比較帳戶、鏈、部署 ID、協定版本、NFT
  地址和託管地址。模擬掛起時的配置變更會使錢包呼叫先前的舊請求無效。歷史意圖保留其原始部署標識。
- 內部市場導航使用 React Router 連結。選項卡本地易失性事務
  因此，覆蓋層可以在運行的應用程式中的路由變更中倖存下來。真正的重新加載或選項卡關閉仍然會丟失非持久的證據，並且仍然存在明確的恢復限制。
- 目錄播種獲得現有的獨佔門，然後拒絕任何不完整的維護
  在開啟資料庫或變更目錄行之前進行標記。只有匹配的恢復命令才能解析該標記。
- 當子進程產生時，諮詢鎖定助手捕捉一個完成承諾。正常退出，
  訊號退出、子錯誤、重複釋放和複合清理都觀察到相同的結果。
- 原始的近期事件提要保留了規範的和替換的審計歷史記錄。每場活動都承載著
  `canonical`、`scanComplete`、以及區塊的`sourceLogScopeHash`；消費者必須評估每行的這些字段，而不是從響應級別檢查點推斷有效性。
- 架構規則評估已解析目標的套件所有權以及書面導入
  說明符。相對路徑、別名和重新匯出不能繞過 Web 到資料庫邊界。
- 有狀態託管套件獨立地對銷售資金和可索賠的付款索賠進行總和。它斷言
  該預期未償金額等於 `totalLiability`，且該合約餘額涵蓋該獨立計算的金額。成功的轉換計數器與操作嘗試保持分離。

## 後果

模擬期間的部署替換不會因過時操作產生錢包請求。已經開始的成功錢包請求仍然遵循現有的哈希和`UNKNOWN`恢復規則； UI 並不聲稱它從未提交過。

即使在作業系統鎖被釋放之後，不完整的維護標記也可以防止目錄突變。只讀診斷和身份匹配恢復仍然可用。

事件 API 是審核來源，而非僅限規範的業務來源。流離失所的事件仍然是可檢查的，並且可以在不刪除其來源證據的情況下再次成為規範。每個事件的來源範圍與回應包絡的目前投影範圍不同。

額外的契約不變量強化了有關記錄會計的證據。它仍然是本地 Foundry 證據，並不構成外部審計或公共網路安全聲明。
