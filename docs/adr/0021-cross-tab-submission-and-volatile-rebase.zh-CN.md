# ADR 0021：交叉表提交所有权和易失性证据变基

[English](0021-cross-tab-submission-and-volatile-rebase.md) · [繁體中文](0021-cross-tab-submission-and-volatile-rebase.zh-TW.md)

- **状态：**已接受
- **日期：** 2026-09-22

## 背景

交易功能之前将相同意图的提交所有权保留在模块级 `Set` 中。这停止了一个 JavaScript 领域中的重复操作，但两个选项卡都可以保留相同的不可变意图，模拟它并打开钱包请求。

在钱包返回本地存储无法保存的哈希值后，存在单独的恢复边缘。该选项卡在其易失性覆盖层中保留了该哈希值。如果另一个选项卡将相同的持久条目推进到无哈希修订版，则以后的每次持久性重试都会与过时的基本修订版进行比较并失败。当前选项卡继续显示哈希，而重新加载则返回无哈希持久行。

## 决定

1. 浏览器提交使用由完全不可变意图键入的排他 Web 锁。所有权
   在第一个日志写入或其他等待步骤之前开始，并通过模拟、钱包交互、返回哈希持久性和可选的随机数丰富保持不变。
2. 繁忙的相同意图激活在创建一个之前失败并显示 `OPERATION_ALREADY_IN_FLIGHT`
   日志输入、模拟或打开钱包请求。不同的不可变意图使用不同的锁并保持并发。
3. 没有 Web Locks 的浏览器保留现有的模块级回退。后备坐标
   仅在一个 JavaScript 领域中的调用者，并且不提供跨表所有权。
4. 易失性的持久性重试可能会改变新的持久性修订版上唯一的交易证据
   仅当两行描述相同的客户端操作、不可变意图和钱包请求，并且持久行没有交易证据时。持久修订是从当前持久修订前进的。
5. 如果持久行已包含哈希、收据、关联、投影证明或其他
   交易证据，重试失败关闭。它永远不会猜测哪个证据获胜，也永远不会打开另一个钱包请求。

## 后果

- 具有 Web Locks 的一个浏览器配置文件最多可打开一个同时激活的钱包请求
  跨选项卡的不可变意图。
- 关闭所有者选项卡会在浏览器生命周期中释放其 Web Lock。然后另一个选项卡可能会
  获取所有权并且必须开始新的显式操作，而不是继承未知的内存中回调。
- 在并发无哈希恢复修订后，返回的哈希可以变得持久，而无需擦除
  该修订版的不可变上下文。
- 没有 Web Locks 的跨设备协调和跨选项卡协调仍然在范围之外
  保证。在升级成功之前，仅易失性证据仍然无法在重新加载后幸存。

## 验证

- `submit-operation.test.ts` 证明在日志创建、模拟和之前被拒绝的所有权
  钱包提交。
- `browser-submission-coordinator.test.ts` 涵盖同意图排除、独立密钥和锁
  成功或失败后释放。
- `local-storage-journal.test.ts` 涵盖了并发无哈希修订上的安全哈希变基，以及
  拒绝覆盖有冲突的持久交易证据。
- `journal-multitab.spec.ts`使用两个真实的Chromium页面来验证跨表提交排除，
  一个钱包请求、独立意图、正常释放和所有者关闭切换。
