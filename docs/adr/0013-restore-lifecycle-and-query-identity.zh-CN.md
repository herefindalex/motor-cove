# ADR 0013：恢复文件集、生命周期所有权和查询身份

[English](0013-restore-lifecycle-and-query-identity.md) · [繁體中文](0013-restore-lifecycle-and-query-identity.zh-TW.md)

- **状态：**已接受
- **日期：** 2026-09-22

## 背景

三个边界使用相关标识符，但没有强制执行相同的生命周期。恢复一次移动一个 SQLite 主文件和 WAL/SHM sidecar，因此恢复可以在前一个活动数据库留下的 sidecar 旁边安装暂存快照。 Bootstrap 使用外部所有权锁，而重置仅使用服务和写入器门。 Web 查询密钥包含部署 ID，但解析的 HTTP 响应仍可能携带来自另一个部署的出处。

## 决定

1. Restore恢复将主文件、WAL和SHM视为一代。在安装分阶段之前
   独立快照时，恢复会将任何剩余的活动 sidecar 移至该操作的隔离区。从隔离区回滚将其主文件和 sidecar 重新组合起来。重复的活动和隔离的 sidecar 是不明确的，并且仍然需要恢复。
2. 重置在维护服务和写入器锁定之前获取相同的外部引导程序所有权。
   它必须在 `anvil_reset` 或文件系统突变之前拥有两者。固定顺序是生命周期所有权、服务门、然后编写者门。
3. Web 快照请求在其查询功能中捕获预期的部署。 HTTP 适配器
   解析电汇合约，然后将响应来源与预期部署进行比较。不匹配的数据会被拒绝，而不是被缓存或重新标记。然后配置轮询可以提供替换部署上下文；轮询不被视为身份验证。

## 后果

- 分阶段备份无法重播它所替换的数据库留下的热 WAL。
- 重置不能与引导交易或其持久链种子日志竞争。
- 查询键仍然是缓存命名空间；响应来源是独立的运行时检查。
- SQLite 碰撞测试使用线束拥有的临时数据库和被杀死的子写入器。他们不
  声称硬件断电行为。

## 验证

- `tests/recovery/backup-restore.test.ts` 在子进程中创建一个已提交的热 WAL，并杀死它
  过程，重现仅主文件开关，并验证恢复返回备份值。
- `tests/database/reset-cli.test.ts`持有真正的自举程序`flock`，证明`anvil_reset`不是
  调用，释放所有权，并证明重置可以完成。
- `apps/web/src/integrations/http/motorcove-api.test.ts` 检查 Sale、车辆和系统快照
  拒绝不同的部署，不要填充错误的 TanStack Query 缓存条目，在替换部署密钥下恢复，并接受等效的十六进制大小写。
