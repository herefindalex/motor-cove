# ADR 0022：引導快照邊界和對帳發布新鮮度

[English](0022-bootstrap-snapshots-and-reconciliation-publication.md) · [简体中文](0022-bootstrap-snapshots-and-reconciliation-publication.zh-CN.md)

- **狀態：**已接受
- **日期：** 2026-09-22

## 背景

Bootstrap擁有鏈部署、種子交易、資料庫註冊、目錄資料、投影追趕及其完成收據。它的獨佔生命週期鎖與備份和恢復使用的服務鎖和寫入器鎖是分開的。因此，標準備份可以在註冊之後但引導程式完成之前複製已部署的資料庫。後來恢復舊的資料庫留下了新的種子日誌和引導收據，發布了混合生成。

對帳比較投影和一個檢查點區塊和雜湊的鏈狀態。它在可能的長時間比較之前對最新的頭部進行了採樣，並在發布新鮮度時重複使用了該樣本。因此，在比較過程中前進的頭部可以報告為 `CURRENT`。

## 決定

1. 標準備份在維護鎖定之前取得共用引導程式所有權。恢復獲取
   維護鎖定之前的獨佔引導程式所有權。活動引導、復原和標準快照工作不能在一個託管環境中重疊。
2. 遷移安全備份可以明確地重複使用生產已經擁有的引導程式所有權
   引導調用者。這可以避免重新取得不可重入生命週期鎖，同時保留相同的所有權邊界。
3. 部署的標準備份必須包含種子日誌和引導收據，或兩者都不包含。
   不完整的對在創建和驗證期間會被拒絕。
4. 恢復將活動部署、種子日誌和引導接收位元組與
   隔離前驗證備份。僅資料庫還原不會將較舊的快照與較新的引導產生結合。
5. 對帳錨定比較後再次讀取最新的頭部。出版品樣本
   確定 `CURRENT` 或 `PROJECTION_LAGGING`。如果該樣本不可用，則持久嘗試是 `UNVERIFIABLE / HEAD_UNKNOWN` 以及實際的傳輸原因。

## 後果

- 部分引導資料庫不會作為可恢復的標準備份發布。
- 如果快照後 bootstrap sidecar 發生更改，則在隔離之前恢復會失敗。
- 錨定匹配在其檢查點仍然有效，而發布新鮮度反映了稍後的情況
  頭。當無法觀察到最新的頭部時，該報告絕不會發明滯後。
- 鎖定仍為本地諮詢 `flock`；沒有引入分散式所有權主張。

## 驗證

- 备份/恢复测试持有真实的引导锁，执行真实的better-sqlite3快照，拒绝
  不完整的和遺留的 sidecar 對，在隔離之前拒絕更改的活動 sidecar，並證明遷移安全備份在呼叫者持有的引導程式所有權下有效。
- 對帳整合測試使用真實記憶體中的 SQLite 和
  受控鏈客戶端。除了現有的首次讀取失敗案例之外，它們還涵蓋了比較過程中頭部前進和出版物頭部讀取失敗的情況。
