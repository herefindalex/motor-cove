# ADR 0012：可恢復維護和日誌修訂

[English](0012-resumable-maintenance-and-journal-revisions.md) · [简体中文](0012-resumable-maintenance-and-journal-revisions.zh-CN.md)

- 狀態：已接受
- 日期：2026-09-22

## 背景

投影維護和瀏覽器事務提交都跨越持久邊界。重新索引可能會在記錄其目標後停止，並且瀏覽器可能會等待另一個選項卡，然後才能保留意圖或傳回的雜湊值。在復原上重新計算重新索引目標、刪除沒有存檔的來源證據或將掛鐘時間視為寫入版本會使持久記錄與實際運行的操作不一致。

## 決定

1. 新的重新索引一次捕獲合格的目標區塊和哈希值。復原的重建索引顯示
   目標來自其匹配的維護標記，驗證相同的區塊和哈希兩次，即使鏈頭前進，也保留原始目標。更改後的目標錨點無法關閉。
2. 維護鎖在獲得後立即進入其清理範圍。標記解析，
   身份檢查、恢復解析、模式驗證、資料庫開啟和操作回調都會在失敗時釋放相同的鎖定。
3. 來源刷新重新索引在刪除之前建立並驗證正常環境備份
   活動標題或事件。驗證後的備份ID首先寫入維護標記。恢復驗證相同的備份。如果無法建立或驗證它，則活動來源證據不會受到影響。
4. 每個瀏覽器日誌條目都附帶每個操作的修訂版本。寫入比較其預期
   修訂並將其升級到現有的部署 Web Lock 中。不符返回 `JOURNAL_REVISION_CONFLICT`； `updatedAt`保留顯示證據並且從不決定寫入順序。如果錢包傳回的雜湊值與較新的無雜湊恢復版本競爭相同的不可變意圖，則提交會將雜湊值合併到最新版本中。不同的意圖或哈希仍然是衝突，並回退到顯式的非持久處理。
5. 在等待 `AWAITING_WALLET` 後提交重新檢查完整的即時操作上下文
   在呼叫錢包之前立即寫入和 。

## 後果

- 操作員可以在執行指令後使用原始 `--from` 值重新執行記錄的重新索引指令。
  無需追逐移動的頭部即可中斷。
- 源刷新備份保留了用於診斷的規範和移位的原始證據，但它們不
  將本機備份轉為公共存檔 - RPC 可用性。
- 過時的瀏覽器工作無法報告被默默丟棄的持久更新。來電者須攜帶
  轉發 `save()` 傳回的條目，以便下次寫入使用保留的修訂版本。
- 當另一個操作寫入時，易失性覆蓋不會刪除其先前的持久意圖
  共享部署日誌。
- Web 鎖定一個瀏覽器設定檔中的邊界座標標籤。它不協調設備，
  並且易失性哈希仍然無法在真正的文檔重新加載後倖存下來。

## 驗證

單元和整合測試涵蓋固定目標復原、更改錨點拒絕、格式錯誤和不匹配的標記清理、刷新前備份保存、持久化後上下文失效、掛鐘回滾、修訂衝突處理和交易復原。真正的 Chromium 多選項卡測試涵蓋並發編寫器、過時修訂拒絕和編寫器選項卡切換。
