# ADR 0007：序列化恢復證據並對運行時鏈故障進行分類

[English](0007-concurrent-recovery-evidence.md) · [简体中文](0007-concurrent-recovery-evidence.zh-CN.md)

- **狀態：** 在本機運行時接受並實施
- **範圍：** 投影維護、Indexer輪詢、瀏覽器交易驗證

## 背景

投影重新索引重複使用持久性區塊和事件，瀏覽器驗證可以與隨機數豐富或其他驗證請求重疊，而 JSON-RPC 錯誤並不都意味著同一件事。在每種情況下，將舊的或不可用的觀察結果視為當前事實可能會擦除新的證據或將操作員送入錯誤的恢復程序。

## 決定

重建和重新索引在專有維護門下運行。它們在更改投影狀態之前保留 `PREPARED` 和 `ACTIVE` 標記，在出錯時保留 `FAILED` 標記，並僅在成功後清除標記。重新索引可以重新規範化現有區塊並將其已儲存的事件重新套用到新的投影。每個新批次都會在提交之前驗證其第一個父哈希是否加入了持久檢查點。

瀏覽器驗證為每個請求分配一個產生 ID，並在儲存之前重新載入最新的日誌條目。僅當其生成保持最新時，結果才能更新日誌。可選的隨機數豐富僅將隨機數合併到最新條目。 UI從交易狀態、收貨狀態和投影觀察共同得出當前投影成功；歷史接收證據可以在重組後保留，而不會呈現為當前的成功。

Indexer 將傳輸逾時和連線失敗歸類為暫時不可用。它保留檢查點，標記投影新鮮度 `STALE`，以有界指數退避重試，並讓 API 和 Web 進程繼續。更改的檢查點雜湊、提供者確認的遺失檢查點區塊或其他完整性不符仍然是 `RECOVERY_REQUIRED` 並停止攝取。關閉會停止調度輪詢，等待活動輪詢，然後關閉資料庫寫入器。

### 特定於操作的完成

中斷的投影標記攜帶其部署和恢復標識。通用恢復不會將模式完整性視為回溯、重建和追趕已完成的證據。它返回所需的操作並關閉大門。重新運行確切的操作可能會恢復同一鎖下的標記；更改的參數被拒絕。

目前投影的成功與交易哈希、區塊哈希、日誌索引、部署和投影構建息息相關。如果無法持久保存傳回的交易哈希，則哈希和操作上下文在選項卡本機日誌覆蓋中保持可見，並具有明確重新載入限制。此覆蓋不具有持久性或跨裝置復原能力。

## 權衡

- 瀏覽器產生檢查座標保存的日誌證據但不提供跨設備
  分散式事務。
- 錯誤地將歷史區塊報告為遺失的提供者仍然可以要求操作員
  恢復；逾時或連線錯誤不會。
- 維護仍然是一台受信任主機上的明確停機操作。
- 退避保持過時的讀取可用，同時將後續重試嘗試延遲最多八次
  秒。

## 後果

目前的有效性和歷史證據仍然是分開的。 投影維護無法向普通讀取器或寫入器公開中間版本。本地進程管理程式不會僅僅因為 Indexer 退出而終止 API 和 Web，並且優雅的 Indexer 停止不會在活動輪詢下關閉 SQLite。
